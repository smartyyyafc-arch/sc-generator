RESOLVER DETAILS
================================================================================

1. Registry ProgID Resolver
   Technique:  Read HKCR\ProgID\CLSID from registry
   Speed:      Fast (10-50ms)
   Obfuscation: Low
   Resilience: Medium
   Code Size:  200-300 bytes
   Error Path: None (direct failure)

   Generated Code:
   - Uses WScript.Shell
   - RegRead registry key
   - Returns CLSID string
   - On Error Resume Next for safety

2. WMI StdRegProv Resolver
   Technique:  Use WMI StdRegProv to access registry
   Speed:      Slow (100-500ms)
   Obfuscation: Medium
   Resilience: High
   Code Size:  400-500 bytes
   Error Path: None (direct failure)

   Generated Code:
   - Creates SWbemLocator
   - Connects to registry service
   - Gets StdRegProv object
   - Calls GetStringValue method
   - Uses registry constant 2147483648

3. Encoded Literal Resolver
   Technique:  Embed encoded CLSID with decoder function
   Speed:      Fast (1-5ms decoding)
   Obfuscation: High
   Resilience: N/A (pre-computed)
   Code Size:  300-400 bytes + decoder
   Error Path: Includes decoder functions

   Supported Encodings:
   - XOR:      Random key, hex representation
   - Base64:   Standard Base64 codec
   - Hex:      Direct hexadecimal encoding
   - ROT13:    Character rotation cipher
   - Hybrid:   XOR first, then Base64

   Each includes complete decoder function

4. Hash-based Resolver
   Technique:  Pre-computed hash table for CLSID mapping
   Speed:      Very fast (<1ms)
   Obfuscation: High
   Resilience: Medium
   Code Size:  400-500 bytes
   Error Path: Dictionary lookup failure

   Generated Code:
   - Creates Scripting.Dictionary
   - Adds progid_hash -> clsid entries
   - Looks up by hash value
   - Returns CLSID from mapping

5. Hybrid Resolver
   Technique:  Chain multiple resolvers with fallback
   Speed:      Varies (10-500ms depending on which method succeeds)
   Obfuscation: High
   Resilience: Very High
   Code Size:  600-800 bytes
   Error Path: Falls back to next method

   Default Chain:
   1. Registry ProgID (fast first attempt)
   2. WMI StdRegProv (robust fallback)

   Can be customized with any resolver sequence

================================================================================
OBFUSCATION TECHNIQUES
================================================================================

1. XOR Encoding
   Algorithm:  XOR each byte with random key
   Output:     Hex-encoded obfuscated string
   Decoder:    DecodeXOR function
   Size:       Small
   Speed:      Very fast
   Reversibility: Single-byte XOR, easily reversed with key

2. Base64 Encoding
   Algorithm:  Standard Base64 RFC 4648
   Output:     Base64-encoded CLSID
   Decoder:    Uses MSXML2.DOMDocument
   Size:       Medium
   Speed:      Fast
   Reversibility: Standard Base64, easily decoded

3. Hex Encoding
   Algorithm:  Convert to hexadecimal representation
   Output:     Hex string
   Decoder:    DecodeHex function
   Size:       Small
   Speed:      Very fast
   Reversibility: Direct hex, easily decoded

4. ROT13 Encoding
   Algorithm:  Rotate each letter by 13 positions
   Output:     ROT13-transformed string
   Decoder:    DecodeRot13 function
   Size:       Small
   Speed:      Very fast
   Reversibility: ROT13 is easily reversed (symmetric)

5. Hybrid Encoding
   Algorithm:  XOR first, then Base64
   Output:     Base64-encoded XOR result
   Decoder:    Both DecodeXOR and DecodeBase64
   Size:       Medium
   Speed:      Fast
   Reversibility: Two-layer obfuscation

Security Note: These are obfuscation (anti-pattern matching), not encryption.
A determined analyst can reverse them. Use for:
- Evading simple pattern detection
- Making static analysis harder
- Adding complexity layers
DO NOT use for security-critical protection

SECURITY ANALYSIS
================================================================================

What Gets Hidden:
  ✓ Plaintext CLSIDs (if using encoding)
  ✓ Static GUID patterns (via obfuscation)
  ✓ Direct hardcoded object names

What Remains Visible:
  ✗ WScript.Shell creation (if using registry method)
  ✗ WMI Locator creation (if using WMI method)
  ✗ Registry access patterns (leaves audit trail)
  ✗ COM method invocations after instantiation
  ✗ Process execution from COM objects

Detection Methods:
  - Behavioral monitoring: Detects registry access, WMI queries
  - Memory inspection: Decoded CLSID visible in process memory
  - Code analysis: Can reverse simple encodings with effort
  - WMI event tracing: Can log WMI provider calls
  - ETW tracing: Windows Event Tracing can capture details

Mitigations:
  1. Use Hybrid resolver for maximum resilience
  2. Combine with other obfuscation techniques
  3. Layer multiple encoding schemes
  4. Use WMI method instead of registry for reduced audit trail
  5. Add junk code and delays for behavioral evasion
  6. Clear memory after CLSID resolution

Limitations:
  - Not encryption, just obfuscation
  - Determined analyst can reverse techniques
  - Runtime behavior is more detectable than static code
  - Multi-layer approach necessary for serious use

USAGE RECOMMENDATIONS
================================================================================

Choose Registry Method When:
  ✓ Small code size critical
  ✓ Fast execution required
  ✓ Audit trail not a concern
  ✓ Simplicity preferred
  ✗ Don't use if stealth is priority

Choose WMI Method When:
  ✓ Reduced audit trail desired
  ✓ Registry access monitoring active
  ✓ More sophisticated evasion needed
  ✓ WMI infrastructure available
  ✗ Don't use if execution speed critical

Choose Encoded Method When:
  ✓ CLSID must not appear in plaintext
  ✓ Pattern matching evasion needed
  ✓ Static analysis protection priority
  ✓ Don't mind slightly larger code
  ✗ Don't use if decoder function detected

Choose Hash Method When:
  ✓ Execution speed critical
  ✓ Multiple CLSIDs needed
  ✓ Pre-computation acceptable
  ✓ Don't mind larger code footprint
  ✗ Don't use if code size critical

Choose Hybrid Method When:
  ✓ Maximum resilience needed
  ✓ Code size not critical
  ✓ Adapt to any configuration
  ✓ Guaranteed success important
  ✗ Don't use if execution speed critical

Recommended Combinations:
  1. High Stealth:     Hybrid resolver + Encoded literals
  2. High Speed:       Hash resolver alone
  3. High Resilience:  Hybrid resolver with 3+ fallbacks
  4. Balanced:         Registry + WMI hybrid
  5. Forensics Evasion: WMI resolver + Encoded CLSID
