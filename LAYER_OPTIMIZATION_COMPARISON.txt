================================================================================
MATHEMATICAL ANALYSIS
================================================================================

Expansion Factors:
  • Raw String: 1.0x (baseline)
  • Array (JSON): 1.5-6.6x (depends on input length)
  • Base64: 1.33x (4 chars per 3 input chars)
  • Hex: 2.0x (2 chars per 1 input char)

Order 1 (Optimal): Array → Base64 → Hex
  Total Expansion = (Array expansion) × 1.33 × 2.0
  = (Array-dependent) × 2.66

Order 2 (Suboptimal): Base64 → Hex → Array
  Total Expansion = 1.33 × 2.0 × (Array expansion)
  = 2.66 × (Array expansion)

  Same math, but intermediate steps create larger values to compress
  in the Array layer.

Why Array→Base64→Hex wins:
  1. Array encoding creates small, compressible JSON
  2. Base64 efficiently compresses the JSON notation
  3. Final Hex encoding works on smaller intermediate

Why Base64→Hex→Array loses:
  1. Base64 operates on raw string (less compressible)
  2. Hex doubles the size of Base64 output
  3. Array encoding then acts on larger intermediate
