For NamingStrategyConfig:
  primary_strategy              → Main strategy (e.g., COMMON_TOOLS)
  fallback_strategies           → Backup strategies (list)
  randomize_case                → True/False (case variation)
  chunk_numbering               → "sequential", "hex", or "random"
  seed                          → Optional int (for reproducibility)

For EnhancedEnvVarConfig:
  naming_strategy               → Primary strategy
  fallback_naming_strategies    → List of fallback strategies
  use_strategy_rotation         → True/False (rotate through strategies)
  encoding                      → BASE64, HEX, RAW
  scope                         → PROCESS, USER, or SYSTEM
  track_metadata                → True/False (store metadata)
  include_checksum              → True/False (SHA256)

Pattern 1: Simple Single Strategy
──────────────────────────────────
config = NamingStrategyConfig(primary_strategy=NamingStrategy.COMMON_TOOLS)
namer = EnvVarNamingStrategy(config)
names = namer.generate_chunk_names("PAYLOAD_ID", 4)


Pattern 2: With Rotation
─────────────────────────
config = NamingStrategyConfig(
    primary_strategy=NamingStrategy.COMMON_TOOLS,
    fallback_strategies=[NamingStrategy.BUILD_SYSTEM, NamingStrategy.CLOUD]
)
namer = EnvVarNamingStrategy(config)
names = namer.generate_with_rotation("PAYLOAD_ID", 6)


Pattern 3: Environment-Aware
──────────────────────────────
multi = MultiStrategyNamer()
config = multi.generate_recommendation("cloud")
namer = EnvVarNamingStrategy(config)
names = namer.generate_chunk_names("PAYLOAD_ID", 4)


Pattern 4: Full Storage Integration
────────────────────────────────────
storage_config = EnhancedEnvVarConfig(
    naming_strategy=NamingStrategy.COMMON_TOOLS,
    encoding=EnvVarEncoding.BASE64,
    scope=EnvVarScope.PROCESS
)
writer = EnhancedEnvVarWriter(storage_config)
success, names, msg = writer.write_to_env("SECRET_ID", payload)


Pattern 5: Strategy Rotation with Storage
──────────────────────────────────────────
config = EnhancedEnvVarConfig(
    use_strategy_rotation=True,
    fallback_naming_strategies=[
        NamingStrategy.BUILD_SYSTEM,
        NamingStrategy.DEVELOPMENT,
        NamingStrategy.CLOUD
    ]
)
writer = EnhancedEnvVarWriter(config)
success, names, msg = writer.write_to_env("SECRET_ID", payload)

DETECTION EVASION CAPABILITIES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Against Signature Matching:
  ✓ Multiple strategies prevent fixed signatures
  ✓ Real prefixes match legitimate tools
  ✓ Rotation makes signatures obsolete

Against Pattern Analysis:
  ✓ Legitimate suffix combinations look intentional
  ✓ Mix of strategies prevents pattern detection
  ✓ Case variation obscures patterns

Against Entropy Analysis:
  ✓ Legitimate prefixes reduce entropy (looks good)
  ✓ Blends with real environment variables
  ✓ Not pure random (looks intentional)

Against Regex Scanning:
  ✓ Uses real platform conventions
  ✓ Avoids suspicious patterns
  ✓ Matches known tool naming schemes

Against Behavioral Analysis:
  ✓ Variable usage aligns with tool purposes
  ✓ Metadata can be crafted to match expectations
  ✓ Rotation prevents obvious behavior patterns

Against Machine Learning:
  ✓ Uses real prefixes (in training data)
  ✓ Multiple strategies for variation
  ✓ Hard to distinguish from legitimate variables

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Environment Variable Name Requirements:
  ✓ Must start with letter or underscore
  ✓ Only alphanumeric and underscore allowed
  ✓ Typically 8-32 characters
  ✓ UPPER_CASE is standard on Unix/Windows
  ✓ Underscores used as separators

All strategies in this suite generate names that pass these requirements.

KEY PRINCIPLES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. LEGITIMACY FIRST
   The best variable name is one that looks exactly like a variable that
   SHOULD be there in that environment.

2. CONTEXT MATTERS
   Different environments have different expectations. Cloud deployments
   expect AWS_, containers expect DOCKER_, etc.

3. ROTATION PREVENTS PATTERNS
   Using different strategies for different chunks defeats pattern-based
   detection methods.

4. REAL PREFIXES WORK BEST
   Prefixes from real, popular tools are far more legitimate than random
   strings.

5. BLENDING IS BETTER THAN STEALTH
   Looking like real system configuration is better than trying to hide.
