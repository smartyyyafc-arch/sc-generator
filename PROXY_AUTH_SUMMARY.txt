KEY FEATURES
================================================================================

Authentication Methods:
  1. Basic Authentication (RFC 7617)
     - Simple username/password encoding
     - Fast and widely supported
     - Recommended for HTTPS only

  2. Digest Authentication (RFC 7616)
     - Challenge-response mechanism
     - MD5 and SHA-256 support
     - More secure than Basic
     - Handles nonce count and QOP

  3. NTLM Authentication
     - Three-message handshake
     - Windows/Corporate environment support
     - Domain and workstation configuration
     - Complex but highly compatible

  4. Certificate-Based Authentication (mTLS)
     - Client certificate and key support
     - CA bundle verification
     - Highest security level
     - Service-to-service communication

Core Capabilities:
  - Multi-scheme authentication handler
  - Challenge-response support
  - Configuration validation
  - Secure credential handling
  - JSON export (no credentials)
  - Custom header support
  - Proxy URL normalization
  - Timeout configuration
  - SSL/TLS verification options

================================================================================
API OVERVIEW
================================================================================

Main Class: ProxyAuthHandler

Methods:
  - __init__(config: ProxyConfig)
    Initialize handler with configuration

  - get_auth_headers() -> Dict[str, str]
    Get authentication headers for initial request

  - handle_challenge(challenge: str) -> Dict[str, str]
    Generate response to server authentication challenge

  - get_proxy_url() -> str
    Get proxy URL without embedded credentials

  - get_connection_config() -> Dict[str, Any]
    Get complete configuration for connection

  - to_json() -> str
    Export configuration as JSON (credentials excluded)

Convenience Function: create_auth_handler()
  Create handler with simplified syntax

  Example:
    handler = create_auth_handler(
        proxy_url="http://proxy:8080",
        auth_type="basic",
        username="user",
        password="pass"
    )

================================================================================
USAGE EXAMPLES
================================================================================

Basic Usage:
-----------
from proxy_auth_handler import create_auth_handler

handler = create_auth_handler(
    proxy_url="http://proxy.example.com:8080",
    auth_type="basic",
    username="user",
    password="pass"
)

headers = handler.get_auth_headers()


With requests Library:
---------------------
import requests

session = requests.Session()
session.proxies = {'http': handler.get_proxy_url()}
session.headers.update(handler.get_auth_headers())
response = session.get('http://api.example.com')


Certificate Authentication:
---------------------------
handler = create_auth_handler(
    proxy_url="https://proxy:8443",
    auth_type="certificate",
    cert_path="/path/to/cert.pem",
    key_path="/path/to/key.pem"
)

config = handler.get_connection_config()
session.cert = (config['client_cert'], config['client_key'])


NTLM with Domain:
----------------
handler = create_auth_handler(
    proxy_url="http://proxy:8080",
    auth_type="ntlm",
    username="domain\\user",
    password="pass",
    domain="CORPORATE"
)


Error Handling:
--------------
from proxy_auth_handler import ProxyConfig, AuthType

try:
    config = ProxyConfig(
        proxy_url="http://proxy:8080",
        auth_type=AuthType.BASIC,
        username="user",
        password="pass"
    )
    handler = ProxyAuthHandler(config)
except ValueError as e:
    print(f"Configuration error: {e}")
except FileNotFoundError as e:
    print(f"File error: {e}")

================================================================================
CONFIGURATION OPTIONS
================================================================================

ProxyConfig Parameters:

Required:
  - proxy_url: str
    Proxy server URL (http:// or https://)

Authentication (type-dependent):
  - auth_type: AuthType (default: BASIC)
    Authentication method
  - username: str (optional)
    Username for Basic/Digest/NTLM
  - password: str (optional)
    Password for Basic/Digest/NTLM
  - cert_path: str (optional)
    Path to client certificate for certificate auth
  - key_path: str (optional)
    Path to private key for certificate auth

Advanced:
  - ca_bundle: str (optional)
    Path to CA certificate bundle
  - domain: str (optional)
    Windows domain for NTLM
  - workstation: str (optional)
    Workstation name for NTLM
  - timeout: int (default: 30)
    Connection timeout in seconds
  - verify_ssl: bool (default: True)
    Verify SSL certificates
  - custom_headers: Dict[str, str] (default: {})
    Additional HTTP headers
  - ntlm_flags: int (default: 0x00000017)
    NTLM negotiation flags

================================================================================
INTEGRATION PATTERNS
================================================================================

Pattern 1: HTTP Client Integration
  - Create handler once
  - Get headers and proxy URL
  - Use in session setup
  - Reuse for multiple requests

Pattern 2: Challenge-Response Handling
  - Get initial headers
  - If 407 received, extract challenge
  - Call handle_challenge() with challenge
  - Retry request with response headers

Pattern 3: Environment-Based Configuration
  - Read proxy settings from environment
  - Read credentials from secure vault
  - Create handler with configuration
  - Safe to export configuration

Pattern 4: Certificate Rotation
  - Create new handler with new cert paths
  - Existing handlers continue to use old certs
  - No state interference between handlers

Pattern 5: Custom Headers
  - Add authentication headers via handler
  - Add custom headers via custom_headers param
  - All headers combined in get_auth_headers()
  - Clean separation of concerns

================================================================================
KNOWN LIMITATIONS
================================================================================

1. Proxy Requirements
   - Proxy must support chosen authentication method
   - Some proxies may not support all schemes
   - NTLM requires three-message handshake

2. NTLM Specific
   - More complex than other methods
   - Higher computational overhead
   - Requires domain/workstation information
   - May require special HTTP client support

3. Certificate Authentication
   - Requires valid certificate/key pair
   - Certificate must be trusted by proxy
   - Higher setup complexity
   - Key file must be protected

4. HTTP Client Support
   - Some clients may not support challenge handling
   - Manual retry needed for some schemes
   - May need adapter/middleware for automatic handling

5. Platform-Specific
   - NTLM primarily for Windows/Active Directory
   - Certificate paths platform-dependent
   - Some features may need adjustment for edge cases

================================================================================
TROUBLESHOOTING GUIDE
================================================================================

Issue 1: 407 Proxy Authentication Required
  - Verify credentials are correct
  - Check proxy URL format is correct
  - Try different authentication type
  - Verify proxy server supports chosen auth method
  - Check network connectivity to proxy

Issue 2: NTLM Authentication Fails
  - Use correct format: domain\username
  - Verify domain name is correct
  - Check proxy supports NTLM
  - Verify workstation parameter if needed
  - Try basic auth as fallback

Issue 3: Certificate Validation Fails
  - Verify certificate path is correct
  - Check certificate is not expired
  - Verify CA bundle includes root CA
  - Try with verify_ssl=False (development only)
  - Check certificate format is valid

Issue 4: Connection Timeout
  - Increase timeout parameter
  - Check network connectivity
  - Verify proxy server is running
  - Check for firewall blocking

Issue 5: Custom Headers Not Included
  - Verify custom_headers parameter
  - Check get_auth_headers() includes all headers
  - Verify header values are correct
