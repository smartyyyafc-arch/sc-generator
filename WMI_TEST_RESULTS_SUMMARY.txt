================================================================================
TECHNICAL NOTES
================================================================================

1. WMI vs Win32 API
   - WMI is higher-level abstraction over Win32
   - Can be monitored while Win32 calls are harder to track
   - Both provide command execution capabilities

2. Process Creation via WMI
   - Appears as WmiPrvSe.exe spawning processes
   - No parent process relationship to calling script
   - Executes as SYSTEM if run with admin privileges

3. WMI Event Subscriptions
   - Very stealthy persistence mechanism
   - Runs before antivirus loads in boot sequence
   - Survives reboots automatically
   - Difficult to detect without WMI-specific monitoring

4. Performance Impact
   - WMI queries can be resource-intensive
   - Event subscriptions add minimal overhead
   - Process creation via WMI slightly slower than direct API

5. Compatibility
   - WMI API compatible across all Windows versions
   - VBScript works on all Windows (XP+)
   - Python support requires additional modules
