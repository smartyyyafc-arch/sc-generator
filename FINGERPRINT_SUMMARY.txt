CRITICAL ISSUES (5)
═══════════════════════════════════════════════════════════════════════════

1. STRING ENCRYPTION (_encrypt_strings, lines 270-276)
   ─────────────────────────────────────────────────────
   Problem: Encrypts ENTIRE file with Caesar cipher (simple byte rotation)

   Code:
     encrypted = bytes((b + rotation) % 256 for b in content)

   Impact:
     • PE headers completely corrupted
     • File becomes garbage data
     • No decryption stub included
     • File cannot execute

   Fix: Use proper encryption only on data sections with decryption stub
   Effort: 2-3 hours


2. RANDOM BYTE INSERTION (_obfuscate_imports, lines 260-268)
   ──────────────────────────────────────────────────────────
   Problem: Inserts 100 random bytes at arbitrary position

   Code:
     insert_pos = random.randint(100, len(content) - 100)
     content = content[:insert_pos] + junk + content[insert_pos:]

   Impact:
     • All subsequent file offsets corrupted
     • Section references become invalid
     • PE parser fails
     • File cannot execute

   Fix: Don't insert - use pefile to create proper sections
   Effort: 2-3 hours


3. NAIVE SECTION NAME REPLACEMENT (_randomize_section_names, lines 237-258)
   ────────────────────────────────────────────────────────────────────────
   Problem: Uses string.replace() on binary PE structure

   Code:
     content = content.replace(old_name, new_name, 1)

   Issues:
     • May replace in wrong location (data vs header)
     • PE section names are 8-byte fixed fields
     • Replacement of 5-byte ".text" creates alignment issues
     • Doesn't parse actual PE section headers

   Impact:
     • Section table becomes corrupted
     • Misaligned headers
     • File cannot execute

   Fix: Use pefile to properly modify section headers
   Effort: 1-2 hours


4. JUNK BYTES APPENDED TO FILE END (_modify_pe_sections, line 226)
   ────────────────────────────────────────────────────────────────
   Problem: Simply concatenates 256 bytes to file end

   Code:
     content = content + junk

   Issues:
     • Bytes not part of any PE section
     • PE headers not updated (NumberOfSections, SizeOfImage)
     • Appended data not loaded or executed
     • Easy to remove (just truncate file)

   Impact:
     • Junk is ignored by PE loader
     • Modification has no effect
     • Detectable as appended padding

   Fix: Create proper PE section for junk using pefile
   Effort: 2-3 hours


5. METADATA MODIFICATION AT WRONG OFFSET (_modify_metadata, line 294)
   ──────────────────────────────────────────────────────────────────
   Problem: Modifies bytes 4-7 instead of PE timestamp at offset 0x40

   Code:
     # "Modify timestamp"
     content = content[:4] + bytes(...) + content[8:]

   Issues:
     • Timestamp is at offset 0x40, not 0x04
     • Modifies DOS header (e_lfanew field)
     • Breaks PE file parsing
     • Parameter metadata dict completely ignored

   Impact:
     • Modification at wrong offset
     • File structure corrupted
     • No actual metadata change occurs

   Fix: Parse COFF header properly, use metadata parameter
   Effort: 1-2 hours
