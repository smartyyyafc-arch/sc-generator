WMI EXECUTION TEST - QUICK START GUIDE
================================================================================

WHAT IS THIS?
This test suite verifies WMI (Windows Management Instrumentation) execution
capabilities on Windows systems. It tests connectivity, queries, and command
execution through WMI.

QUICK START (WINDOWS SYSTEM ONLY)

Method 1: VBScript (Recommended - No dependencies)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. On Windows, open Command Prompt or PowerShell
2. Run this command:

   cscript.exe wmi_execution_test.vbs

3. View output directly or save to file:

   cscript.exe wmi_execution_test.vbs > results.txt

4. Check results:
   - Look for "[PASS]" tests = Good/Working capability
   - Look for "[FAIL]" tests = Restricted/Missing capability
   - Success Rate line shows overall WMI functionality

WHAT DO THE RESULTS MEAN?

Result: "Process Creation Capability PASS"
├─ Meaning: Can execute commands via WMI
├─ Threat Level: HIGH
├─ Used By: payload_installer.py, persistence_manager.py
└─ Implication: WMI can execute arbitrary code

Result: "WMI Connection FAIL"
├─ Meaning: WMI service is not available
├─ Threat Level: NONE (for WMI-based threats)
├─ Implication: WMI-based payloads won't work
└─ Status: System is partially protected against WMI threats

Result: "Registry Access PASS"
├─ Meaning: Can read/write registry via WMI
├─ Threat Level: MEDIUM-HIGH
├─ Used By: persistence_manager.py (registry persistence)
└─ Implication: Can create Run keys, startup entries

IF RESULTS SHOW THREATS

If tests show WMI command execution is available:

1. IMMEDIATE: Check for suspicious processes
   tasklist /v | find "wmi"

2. CHECK: WMI event subscriptions
   wmic os get Caption,Version
   Get-WmiObject -Class __EventFilter

3. RESTRICT: Disable unnecessary WMI access
   - Use Windows Defender settings
   - Apply Group Policy restrictions
   - Use EDR/antivirus to block WMI process execution

4. MONITOR: Enable WMI activity logging
   - Windows Event Viewer
   - Security event logging
   - WMI Event Subscription logging

TROUBLESHOOTING

Problem: "Access Denied" error
Solution:
  1. Try running as Administrator
  2. Check WMI service status: Get-Service WinRM
  3. Check if WMI denylist is active

Problem: "WMI Connection Failed"
Solution:
  1. Verify WMI service running: sc query winmgmt
  2. Check if disabled: dism /online /enable-feature /featurename:WMI
  3. Restart WMI service: net stop winmgmt && net start winmgmt

Problem: Tests show FAIL but expect PASS
Solution:
  1. Check Windows Event Viewer for errors
  2. Verify WMI repository health: wmidiag.exe
  3. Check antivirus WMI restrictions
  4. Review Group Policy WMI restrictions

Problem: All tests pass - what now?
Solution:
  1. Implement WMI monitoring per documentation
  2. Restrict WMI process creation
  3. Monitor for malicious WMI event subscriptions
  4. Check for WMI persistence in registry
