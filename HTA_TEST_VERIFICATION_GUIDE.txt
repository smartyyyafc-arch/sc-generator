================================================================================
                    HTA TEST VERIFICATION GUIDE
                 Step-by-Step Instructions for Testing
================================================================================

OVERVIEW
--------
This guide provides instructions for verifying HTA silent execution capabilities.
Tests should be performed on a Windows system (7/10/11) in an isolated environment.


ENVIRONMENT REQUIREMENTS
========================

Hardware/Software:
- Windows operating system (7, 8.1, 10, or 11)
- Administrator access to the test machine
- Virtual machine recommended (snapshot capability)
- Network isolation or controlled firewall rules
- Optional: Wireshark or NetMon for network monitoring
- Optional: Sysmon for advanced process monitoring

Test Isolation:
- Do NOT use production systems
- Disable real-time antivirus monitoring (or whitelist test directory)
- Use VM snapshot to restore after testing
- Disable network access if testing payload execution


TEST 1: BASIC HTA DETECTION
===========================

Objective: Verify HTA can detect its execution environment

Steps:

1. Copy test_hta_basic.hta to your test system
2. Double-click test_hta_basic.hta
3. Observe window opens with test results
4. Expected results:
   ✓ "mshta.exe detected" message should appear (green)
   ✓ "WScript.Shell object created" message appears
   ✓ "File system access (FSO)" message appears
   ✓ "Registry access available" message appears

Verification:
- If all tests show checkmarks, HTA environment is confirmed
- If any show X (red), system may have restrictions
- Note any failed tests for subsequent analysis

Success Criteria:
- Window displays test results
- Multiple tests show success indicators
- No security warnings during execution
- Window closes normally when requested


TEST 2: SILENT COMMAND EXECUTION
=================================

Objective: Verify commands can execute without visible window

Steps:

1. Copy test_hta_silent_exec.hta to your test system
2. Open Command Prompt as Administrator
3. Run: mshta.exe test_hta_silent_exec.hta
4. Observe window opens minimized in taskbar
5. Check output log for execution results
6. Window should auto-close after 5 seconds

Expected Behavior:

✓ No console window (cmd.exe) appears at any point
✓ Minimal HTA window in taskbar only
✓ Log shows successful command execution
✓ Log shows file operations completed
✓ Auto-close happens without user interaction
✓ Test files created in %TEMP% folder (if allowed)

Verification:
1. Check %TEMP% folder for test files created during execution
   - Look for files named hta_test_*.txt
   - Verify file contents match expected output

2. Check Registry for test modifications
   - Run: regedit.exe
   - Navigate to: HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
   - Look for "HTA_TEST_Entry" - should NOT exist (was cleaned up)

3. Monitor Process Creation
   - Open Task Manager
   - Go to Processes tab
   - Watch for child processes of mshta.exe
   - Expected: cmd.exe, powershell.exe should appear briefly

Success Criteria:
- Window is minimal/hidden during execution
- No user prompts during execution
- Test files created and cleaned up silently
- Registry modifications occur without prompts
- Window closes automatically


TEST 3: REGISTRY ACCESS SILENT MODIFICATION
=============================================

Objective: Verify registry can be modified without user prompts

Steps:

1. Open Registry Editor: regedit.exe
2. Navigate to: HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
3. Take screenshot of current state
4. Run: mshta.exe test_hta_silent_exec.hta
5. Wait for completion
6. Check Run key again in Registry Editor
7. Take screenshot to compare before/after

Expected Behavior:

During Execution:
✓ No Registry Editor warning dialog
✓ No UAC prompt (unless system is locked down)
✓ No "Access denied" errors
✓ Registry value added silently to Run key

After Execution:
✓ Registry values created by HTA should be removed (auto-cleanup)
✓ No persistent changes left in registry
✓ Run key looks identical to before test

Verification:
1. Check Event Viewer for registry access logs
   - Event ID 4657 (Registry Value Modified)
   - Source: Security log
   - May show registry modifications

2. Check Registry audit settings
   - Right-click on Run key
   - Select Permissions
   - Check "Audit" tab for access logging

3. Monitor with Sysmon (if available)
   - Search for "RegistryEvent" entries
   - Should show mshta.exe -> registry operation

Success Criteria:
- Registry modifications occur without user interaction
- No error dialogs appear
- Changes made and cleaned up automatically
- Audit logs show registry access by mshta.exe

Success Criteria:

TEST 6: UAC PROMPT BEHAVIOR
===========================

Objective: Verify whether UAC prompts appear

Steps - Scenario A (Non-Admin User):

1. Log in as non-administrator user
2. Right-click test_hta_basic.hta
3. Select "Open" or double-click
4. Observe if UAC prompt appears
5. If prompted: note what action requires elevation
6. Document whether execution proceeds after elevation

Steps - Scenario B (Administrator User - No Elevation):

1. Log in as administrator (normal mode, NOT "Run as administrator")
2. Double-click test_hta_basic.hta
3. Observe if UAC prompt appears
4. Registry operations should complete without prompt
5. File system operations should complete without prompt

Steps - Scenario C (Administrator User - Elevated):

1. Open Command Prompt as Administrator
2. Run: mshta.exe test_hta_basic.hta
3. Observe NO UAC prompt (already elevated)
4. All operations execute at elevated level

Expected Behavior:

Scenario A (Non-Admin):
- UAC prompt only if registry access to HKLM required
- File operations in TEMP may not trigger UAC
- Registry HKCU operations should work without UAC

Scenario B (Admin, not elevated):
- No UAC prompts for HKCU operations
- HKLM access may trigger prompt
- File system operations work freely

Scenario C (Admin, elevated):
- No UAC prompts at all
- Full system access available
- All operations silent

Verification:
1. Check Windows Event Log
   - Event ID 4688 for process creation
   - Check ParentImage for UAC elevation
   - Look for TokenElevationType field

2. Monitor with Sysmon
   - Check for UAC prompt events
   - Should see process creation with/without elevation

3. Check Registry keys:
   - HKEY_CURRENT_USER\Volatile Environment\LOGONSERVER
   - HKEY_CURRENT_USER\Volatile Environment\USERDOMAIN
   - Different for admin vs non-admin

Success Criteria:
- Non-admin scenario: Minimal UAC prompts
- Admin non-elevated: No UAC prompts for HKCU
- Admin elevated: Completely silent, no prompts
- Execution completes as expected in all scenarios

TEST 8: PERSISTENCE TEST
=========================

Objective: Verify persistence mechanisms work silently

Steps:

1. Create test persistence HTA with this code:

   var shell = new ActiveXObject("WScript.Shell");
   var runKey = "HKEY_CURRENT_USER\\Software\\Microsoft\\Windows\\CurrentVersion\\Run\\";
   shell.RegWrite(runKey + "PersistenceTest", "notepad.exe", "REG_SZ");

2. Run HTA: mshta.exe persistence_test.hta

3. Verify registry modification:
   - Open regedit.exe
   - Navigate to Run key
   - Should see "PersistenceTest" = "notepad.exe" entry

4. Reboot system

5. After reboot:
   - Check if notepad.exe starts automatically
   - Check registry for entry still present
   - Verify no prompts appeared during startup

Expected Behavior:

During HTA Execution:
✓ No prompts or notifications
✓ Registry entry added silently to Run key
✓ Modification occurs without user knowledge

At Startup/Next Boot:
✓ Registered program launches without prompt
✓ No "New application found" notification
✓ User may not notice persistence
✓ Entry persists across reboots

Verification:

1. Registry Check:
   - Before: Run key doesn't contain entry
   - After HTA: Entry appears in registry
   - After reboot: Entry still present

2. Process Monitor:
   - Shows registry write operation
   - Shows process launch at startup
   - Shows child processes if any

3. Event Log:
   - Process creation for persisted program
   - Registry modification events
   - No error events during execution

Success Criteria:
- Registry entry created silently
- Program launches automatically at next startup
- No user prompts during persistence
- Entry persists across reboots
- Cleanup: Manual registry deletion required
