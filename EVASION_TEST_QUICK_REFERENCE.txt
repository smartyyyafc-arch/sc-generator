COMMON MISTAKES TO AVOID
================================================================================

MISTAKE #1: Trying to Evade Sandbox Behavior Detection
├─ Problem: User interaction detection fails (0.25 score)
├─ Why: Impossible at VBScript level; sandboxes inject events anyway
├─ Solution: Use pre-detection instead (detect sandbox, don't execute)
└─ Impact: Saves 2-3 weeks of futile development effort

MISTAKE #2: Relying on File-Based Persistence
├─ Problem: File system markers easily detected (0.42-0.68 score)
├─ Why: USN Journal captures all file operations forensically
├─ Solution: Use registry_storage_variants instead
└─ Impact: Improves from 0.42 → 0.85 (2x better)

MISTAKE #3: Using Fixed Sleep Intervals
├─ Problem: Timing analysis detects fixed delays
├─ Why: Sleep(5000) followed by same action looks artificial
├─ Solution: Use cryptographic random delays (not pseudorandom)
└─ Impact: Improves timing from 0.60 → 0.70+

MISTAKE #4: Ignoring Pre-Sandbox Detection
├─ Problem: Payload executes in sandbox and gets analyzed
├─ Why: No evasion technique can defeat sandbox at execution time
├─ Solution: Detect sandbox BEFORE running payload
└─ Impact: Eliminates entire Sandbox Detection category (0% → 75%)

MISTAKE #5: Over-Complicating Payload
├─ Problem: Complex code introduces vulnerabilities
├─ Why: More code = more attack surface; harder to maintain
├─ Solution: Use SC-Generator defaults; customize only what's needed
└─ Impact: Reduces bugs by 60%; improves stability
