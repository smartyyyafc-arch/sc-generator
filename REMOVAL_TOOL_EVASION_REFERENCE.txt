                           USAGE PATTERNS

PATTERN 1: Defense in Depth
────────────────────────────────────────────────────────────────────────────

Method          Layer 1         Layer 2             Layer 3
────────────────────────────────────────────────────────────────────────────
Registry        Primary store   Binary blob         Symlink redirect
Task Sched      Hidden task     WMI event           Folder nesting
Services        Service DLL     Driver service      Group hiding
Autoruns        AppInit_DLLs    Winlogon notify     Active Setup

Result: Removal of ANY layer still leaves persistence active


PATTERN 2: Nested Execution
────────────────────────────────────────────────────────────────────────────

Entry Point: Service starts
   ├─ Service DLL loads (from registry)
   │   ├─ Injects into svchost.exe
   │   └─ Creates WMI event subscription
   │
   ├─ WMI event fires periodically
   │   ├─ Loads registry blob (binary data)
   │   └─ Reconstructs payload from fragments
   │
   └─ Fallback: AppInit_DLLs loads into all processes
       ├─ Monitors for persistence removal
       └─ Re-creates removed entries if needed


PATTERN 3: Obfuscation Chain
────────────────────────────────────────────────────────────────────────────

Storage 1: Registry symlink       → Points to alternate location
Storage 2: Registry binary blob   → Hex-encoded data
Storage 3: Registry fragments     → Scattered entries
Execution: PowerShell             → Base64-encoded commands
Loader:    WMI event              → Executes without logging

REGISTRY HIVES EXPLANATION
────────────────────────────────────────────────────────────────────────────

HKCU (HKEY_CURRENT_USER)
  Path: NTUSER.DAT (user profile)
  Monitor: High (MSConfig, Regedit, Autoruns)
  Alternative: HKU\S-1-5-21-*-500

HKLM (HKEY_LOCAL_MACHINE)
  Path: System registry hive
  Monitor: High (MSConfig, Regedit, Autoruns)
  Alternative: Use HKU for per-user entries

HKCR (HKEY_CLASSES_ROOT)
  Path: File association hive
  Monitor: Medium (rarely checked manually)
  Alternative: File extension masquerading

HKCC (HKEY_CURRENT_CONFIG)
  Path: Hardware profile configuration
  Monitor: Low (very rarely checked)
  Alternative: Hidden persistence location

HKU (HKEY_USERS)
  Path: All user profiles
  Monitor: Medium (requires elevated access to inspect)
  Alternative: Per-user persistence


WINDOWS SERVICE TYPES
────────────────────────────────────────────────────────────────────────────

Type 0x1 (SERVICE_KERNEL_DRIVER)
  - Kernel-mode driver (very privileged)
  - Loads early in boot process
  - Difficult to detect/remove

Type 0x2 (SERVICE_FILE_SYSTEM_DRIVER)
  - File system driver (rarely monitored for persistence)

Type 0x10 (SERVICE_WIN32_OWN_PROCESS)
  - Standard Windows service (most common)
  - Runs as separate process
  - Easily visible in Services.msc

Type 0x20 (SERVICE_WIN32_SHARE_PROCESS)
  - Shared process service (grouped with others)
  - Less prominent in GUI


SCHEDULED TASK TRIGGERS
────────────────────────────────────────────────────────────────────────────

BootTrigger (Type 7)
  - Executes at system startup
  - Before user login
  - Before most security software loads

LogonTrigger (Type 8)
  - Executes at user login
  - After security software starts
  - Visible in audit logs

IdleTrigger
  - Executes when system idle
  - No visible activity
  - No event log entries

TimeTrigger (Type 1)
  - Executes at specific time
  - Repeating intervals
  - Visible in event logs

NetworkTrigger
  - Executes when network connects
  - Often missed in analysis


WMI EVENT SUBSCRIPTIONS
────────────────────────────────────────────────────────────────────────────

__EventFilter
  - Defines trigger conditions
  - Examples: System events, WMI instance changes
  - Location: \\.\root\subscription

__EventConsumer
  - Defines action to execute when trigger fires
  - CommandLineTemplate holds payload
  - Location: \\.\root\subscription

__FilterToConsumerBinding
  - Binds filter to consumer
  - Creates persistent association
  - Location: \\.\root\subscription

Query Examples:
  "SELECT * FROM __InstanceModificationEvent WITHIN 30 WHERE TargetInstance ISA 'Win32_PerfFormattedData_PerfOS_System'"
  - Triggers every 30 seconds
  - Based on system performance data
  - No user-visible events


APPINIT_DLLS REGISTRY ENTRIES
────────────────────────────────────────────────────────────────────────────

AppInit_DLLs
  Path: HKLM\Software\Microsoft\Windows NT\CurrentVersion\Windows\AppInit_DLLs
  Value: Path to malicious DLL
  Effect: DLL loads into all processes

LoadAppInit_DLLs
  Path: HKLM\Software\Microsoft\Windows NT\CurrentVersion\Windows\LoadAppInit_DLLs
  Value: DWORD (0 = disabled, 1 = enabled)
  Effect: Controls AppInit_DLLs functionality

RequireSignedAppInit_DLLs
  Path: HKLM\Software\Microsoft\Windows NT\CurrentVersion\Windows\RequireSignedAppInit_DLLs
  Value: DWORD (0 = unsigned allowed, 1 = signature required)
  Effect: Enables/disables signature verification
