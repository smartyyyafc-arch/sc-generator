THE 10 ENCODING STRATEGIES
================================================================================

1. LINEAR (ID=1)
   - Classic multi-layer: Base64 → Hex → Array
   - All intermediate states exposed
   - Size: 441B | Depth: 1 | Time: 0.1ms
   - Use: Compatibility and inspection

2. REVERSE_LINEAR (ID=2)
   - Minimal structure with only array
   - No intermediate state exposure
   - Size: 160B | Depth: 0 | Time: 0.08ms
   - Use: Minimal payload size

3. NESTED_HIDDEN (ID=3)
   - Deep nesting hiding intermediate states
   - Structure: { data: { nested: { payload: [...] } } }
   - Size: 450B | Depth: 3 | Time: 0.1ms
   - Use: Hide transformation steps

4. METADATA_INTERLEAVED (ID=4)
   - Metadata scattered throughout payload
   - Confuses automated parsers
   - Size: 400B | Depth: 1 | Time: 0.11ms
   - Use: Parser obfuscation

5. FLAT_INDEXED (ID=5)
   - Flat object with numbered indices
   - Structure: { __type, __len, _0, _1, ... }
   - Size: 380B | Depth: 1 | Time: 0.12ms
   - Use: Format variation

6. BASE64_ONLY (ID=6)
   - Direct Base64 without intermediate layers
   - Minimal transformation
   - Size: 100B | Depth: 0 | Time: 0.05ms
   - Use: High performance

7. HEX_ONLY (ID=7)
   - Hex split into random-sized chunks
   - Dynamic chunking prevents patterns
   - Size: 220B | Depth: 1 | Time: 0.1ms
   - Use: Size-based detection evasion

8. DEEP_NESTED_DECOYS (ID=8)
   - Multiple nesting with decoy data
   - Multiple false paths
   - Size: 510B | Depth: 4 | Time: 0.15ms
   - Use: Maximum security

9. SPLIT_ARRAY (ID=9)
   - Array split across multiple fields
   - Prevents fragment detection
   - Size: 160B | Depth: 1 | Time: 0.11ms
   - Use: Fragment evasion

10. OBJECT_ARRAY (ID=10)
    - Object with hex-based property names
    - Property names encode positions
    - Size: 420B | Depth: 2 | Time: 0.13ms
    - Use: Property-based detection evasion

================================================================================
SECURITY ANALYSIS
================================================================================

Strengths:
✓ Non-deterministic payloads (same input, different output)
✓ Multiple strategies prevent single-point analysis
✓ Nested obfuscation with 4+ levels possible
✓ Metamorphic metadata confuses static analysis
✓ Optional decoy data creates false analysis paths
✓ Seed-based reproducibility when needed
✓ No hardcoded patterns or constants

Limitations:
✗ Metadata embeds strategy ID (by design)
✗ Deterministic with known seed (feature, not bug)
✗ Fundamental encoding always Base64→Hex→Array
✗ Morphing increases payload size significantly
✗ Nesting keys (_nest0, _nest1) are recognizable

Best Practices:
1. Use with encryption for sensitive data
2. Randomize seeds per session
3. Enable all morphing for high-security
4. Combine with HTTPS/TLS
5. Monitor payload exposure
6. Test compatibility regularly
7. Don't log encoded payloads
8. Rotate seeds periodically
