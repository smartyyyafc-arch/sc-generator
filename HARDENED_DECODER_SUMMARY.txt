================================================================================
The hardened hex decoder extends the base hex decoder variants with comprehensive
obfuscation and anti-analysis techniques to evade static detection mechanisms,
YARA/SIGMA rules, pattern matching, and signature-based security controls.

Three decoder variants are provided:
  1. Command Decoder (HIGH protection) - Shell commands
  2. Script Decoder (HIGH protection) - VBScript/batch scripts
  3. Binary Decoder (MAXIMUM protection) - Executables and binary data

KEY FEATURES - 8 OBFUSCATION LAYERS
================================================================================

1. Variable Name Randomization
   - 8-12 character random names for all functions/variables
   - Unique names generated per execution
   - Defeats hardcoded signature detection

2. Junk Code Injection
   - 3-5 realistic-looking but non-functional code blocks
   - Mimics legitimate VBScript patterns
   - Increases code complexity and analyst overhead

3. Dead Code Paths
   - 2-4 unreachable code branches per decoder
   - If False, While False, impossible conditions
   - Confuses static analysis tools

4. String Chunking
   - Hex payload split into 20-50 character segments
   - Reconstructed via concatenation operators
   - Prevents regex-based hex string detection

5. Anti-Analysis Evasion
   - WMI object creation checks
   - Registry access obfuscation
   - Environment detection code
   - Sandbox detection capabilities

6. Control Flow Obfuscation
   - Unnecessary If/Then branches
   - Random boolean flag evaluations
   - Confuses decompilers and analyzers

7. Object Creation Fragmentation
   - Split CreateObject calls: "WScript." & "Shell"
   - Reassembled at runtime
   - Evades API hook detection

8. Comment-Based Confusion
   - Misleading comments in dead code
   - Obfuscated layer descriptions
   - Misdirects human analysts
