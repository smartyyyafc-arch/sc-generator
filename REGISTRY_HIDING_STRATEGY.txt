OBFUSCATION TECHNIQUES (6 Options)
================================================================================

1. LEGITIMATE_PATH
   Strategy: Uses real Windows registry path templates
   Legitimacy: HIGH (8/10)
   Forensic Evasion: MEDIUM (6/10)
   Seed Required: NO
   Use Case: Casual inspection, moderate threat level

   Example:
   HKCU\Software\Microsoft\Windows\CurrentVersion\WindowsUpdate
   ├── DisplayName
   ├── Description
   ├── Version
   └── Publisher

2. HASH_CHAIN
   Strategy: Cryptographic HMAC chain derivation
   Legitimacy: LOW (4/10)
   Forensic Evasion: VERY HIGH (9/10)
   Seed Required: YES (CRITICAL)
   Use Case: High-value targets, nation-state threat model

   Property: Path completely non-recoverable without seed
   Security: Cryptographic-level strength

3. NAME_MUTATION
   Strategy: Content-based path mutation with integrity binding
   Legitimacy: MEDIUM (6/10)
   Forensic Evasion: HIGH (8/10)
   Seed Required: YES (optional)
   Use Case: Polymorphic payloads, integrity verification

   Property: Same payload → Same path (deterministic)
   Benefit: Payload modification immediately apparent in path change

4. DEPTH_VARIATION
   Strategy: Payload distributed across multiple registry paths
   Legitimacy: MEDIUM (6/10)
   Forensic Evasion: HIGH (8/10)
   Seed Required: NO
   Use Case: Large payloads, distributed resilience

   Property: No single location contains full payload
   Benefit: Missing any chunk prevents reconstruction

5. INTERLEAVED_PATH
   Strategy: Real/fake component mixing
   Legitimacy: HIGH (8/10)
   Forensic Evasion: HIGH (8/10)
   Seed Required: Positions (optional)
   Use Case: Mixed stealth and security, forensic tool evasion

   Pattern: Real + Fake + Real + Fake interleaved
   Benefit: Difficulty distinguishing legitimate from procedural

6. COMPOSITE
   Strategy: Multi-technique hybrid approach with randomization
   Legitimacy: VARIABLE (4-8/10)
   Forensic Evasion: VERY HIGH (9+/10)
   Seed Required: MAYBE (technique-dependent)
   Use Case: Maximum security, polymorphic deployment

   Property: Each instance uses random technique
   Benefit: Defeats technique-specific detection

FORENSIC EVASION FEATURES (ALL TECHNIQUES)
================================================================================

1. Legitimate Appearance
   • Uses real Windows registry paths as templates
   • Names follow Windows PascalCase conventions
   • Includes standard Windows prefixes/suffixes
   • Multiple value names per location (standard pattern)

2. Deep Hierarchical Nesting
   • 4-8 levels of registry nesting (normal for Windows)
   • Requires complete traversal to locate payload
   • Confuses shallow automated scanning
   • Matches legitimate Windows depths

3. Multiple Value Storage
   • Payload distributed across 5+ value names
   • Each value appears independent
   • Mimics legitimate application configuration
   • Impossible to identify single suspicious value

4. Decoy Paths & Data
   • Multiple false positive paths created
   • Decoys contain legitimate-looking data
   • Slows forensic analysis with noise
   • Increases verification burden

5. Procedural Name Generation
   • Names appear authentic yet unique
   • Generated from payload/seed/template
   • Difficult to distinguish from real Windows names
   • Pattern analysis complex without knowledge

6. Seed-Based Protection
   • Cryptographic seeds prevent reconstruction
   • Seed stored separately from registry data
   • Without seed: Path cannot be recovered
   • Provides cryptographic-level security

OPERATIONAL CONSIDERATIONS
================================================================================

Registry Hive Selection:

  HKCU (User-specific):
    + Isolated per user
    + Survives user profile
    - Lost when profile deleted

  HKLM (System-wide):
    + Single location
    + Persists across users
    - Requires admin access

  HKCR (Class registration):
    + Public and readable
    + Standard location
    - Changes common during install

  HKU (All users):
    + Multi-user access
    - Requires admin access

Depth Tuning:

  Depth 3-4: Minimum obfuscation, fast traversal
  Depth 5-6: Standard obfuscation, good balance
  Depth 7-8: Heavy obfuscation, potential detection
  Depth 9+:  Maximum obfuscation, very suspicious

Chunk Size Tuning:

  Small (16-32):   More values, better distribution
  Medium (64-128): Balanced approach, standard
  Large (256+):    Faster recovery, fewer values

Decoy Density:

  Low (1-2):   Subtle, fast scanning
  Medium (3-5): Balanced, standard
  High (6-10):  Heavy obfuscation, significant slowdown
