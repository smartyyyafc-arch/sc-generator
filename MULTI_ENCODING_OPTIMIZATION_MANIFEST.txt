TECHNICAL SPECIFICATIONS
─────────────────────────────────────────────────────────────────────────────

OPTIMAL LAYER ORDER:

  ENCODING DIRECTION:
  ───────────────────
  Input String (5-62 bytes)
    ↓
  [Layer 1] Array Encoding
    └─ Converts string to array of hex pairs
    └─ Output: ["XX", "YY", "ZZ", ...]
    └─ Expansion: ~1.5x
    ↓
  [Layer 2] Base64 Encoding
    └─ Encodes JSON array to Base64
    └─ Output: "WyI0OCIsIjY1Ii..."
    └─ Expansion: 1.5x × 1.33x = ~2x total
    ↓
  [Layer 3] Hex Encoding
    └─ Converts Base64 to hex representation
    └─ Output: "577934734e47..."
    └─ Expansion: 2x × 2.0x = ~4x final
    ↓
  Final Payload (20-248 bytes)

  DECODING DIRECTION (REVERSE):
  ────────────────────────────
  Hex String
    ↓
  [Step 1] Hex Decoding → Base64 String
  [Step 2] Base64 Decoding → JSON Array
  [Step 3] Array Decoding → Original String
    ↓
  Original String (recovered)

IMPLEMENTATION DETAILS:

  Functions Provided:
    ✓ encodeArray() / decodeArray()
    ✓ encodeBase64() / decodeBase64()
    ✓ encodeHex() / decodeHex()
    ✓ multiEncodeOptimized() (with logging)
    ✓ multiDecodeOptimized() (with logging)
    ✓ compactMultiEncodeOptimized() (silent)
    ✓ compactMultiDecodeOptimized() (silent)
    ✓ getPayloadSizes() (utility)

  Complexity:
    ✓ Encoding: O(n) where n = input length
    ✓ Decoding: O(n) where n = encoded length
    ✓ Space: O(n) for intermediate storage
    ✓ No performance degradation vs current
