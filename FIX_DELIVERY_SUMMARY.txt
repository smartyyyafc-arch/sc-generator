ISSUE DESCRIPTION
================================================================================

Vulnerability in create_wscript_hidden_execution() function (lines 226-233 in
vbs_encoder.py and lines 280-287 in vbs_encoder_optimized.py):

1. PLAIN-TEXT COMMAND EXPOSURE
   - Commands embedded directly without encoding
   - Visible to static analysis tools, YARA rules, SNORT signatures
   - Example: "cmd /c echo test" clearly visible in VBS code

2. VARIABLE NAME MISMATCH
   - Multiple _generate_random_name() calls create different variable names
   - Set statement creates one variable, Run uses different variable
   - Results in "Object expected" runtime error
   - Obfuscation completely ineffective

================================================================================
SOLUTION IMPLEMENTED
================================================================================

The fix implements 4 key improvements:

1. STORE VARIABLE NAMES
   - shell_var = self._generate_random_name("shell_")  # Store ONCE
   - Use {shell_var} consistently throughout VBS code
   - No more variable mismatch

2. ENCODE COMMAND
   - encoded_cmd, cmd_var_encoded = self.encode_string_base64(command)
   - "echo test" becomes "ZWNobyB0ZXN0"
   - Command hidden from static analysis

3. ADD DECODER FUNCTION
   - Function DecodeBase64_XXXX(encoded) added
   - Uses MSXML2.DOMDocument (native Windows)
   - Matches existing decoder pattern in codebase

4. CONSISTENT REFERENCES
   - All variables generated before use
   - VBS template uses stored variable names
   - No undefined variable errors
