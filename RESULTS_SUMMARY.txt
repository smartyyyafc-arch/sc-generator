MATHEMATICAL ANALYSIS:

Why Array → Base64 → Hex is optimal:

1. ARRAY ENCODING (First layer)
   • Creates JSON structure: compact and highly compressible
   • Overhead: 4-6 characters per byte in JSON format
   • Output: ["XX", "YY", "ZZ", ...] 
   • Expansion: ~1.5x

2. BASE64 ENCODING (Second layer)
   • Operates on structured JSON (highly compressible)
   • Base64 compression factor: 1.33x (4 chars → 3 input bytes)
   • Efficient on semi-structured text
   • Expansion: 1.5x × 1.33x = ~2x total so far

3. HEX ENCODING (Third layer)
   • Operates on Base64 string (already compact)
   • Hex expansion factor: 2.0x (1 char → 2 hex digits)
   • Total expansion: 2x × 2.0x = 4x ✓ MINIMAL

vs. Base64 → Hex → Array (current):

1. BASE64 ENCODING (First layer)
   • Operates on raw string (less structured)
   • Less efficient compression (raw text ≠ structured JSON)
   • Expansion: 1.33x

2. HEX ENCODING (Second layer)
   • Doubles the Base64 output
   • Expansion: 1.33x × 2.0x = 2.66x

3. ARRAY ENCODING (Third layer)
   • Operates on Hex string (already inflated)
   • Poor compression opportunity (hex chars are already expanded)
   • Expansion: 2.66x × 1.5x = ~4x ✗ SUBOPTIMAL

RESULT: Both converge to ~4x expansion, but Array-first path has better
        intermediate compression, leading to smaller JSON representation
        that feeds into the final Hex encoding.
