SAFETY PRECAUTIONS
==================

IMPORTANT: Test in Isolated Environment

Before Running Tests:

1. Create VM snapshot before testing
2. Disconnect from network (optional but recommended)
3. Disable real-time antivirus (if testing payload execution)
4. Close important applications
5. Document baseline system state

During Testing:

1. Monitor Task Manager for unexpected processes
2. Don't click on unknown dialogs
3. Have restore point ready
4. Don't download actual malware (use test files only)
5. Don't run tests on production systems

After Testing:

1. Review system for any changes
2. Clean up registry entries created by tests
3. Delete test files
4. Restore from snapshot if concerned
5. Run antivirus scan to be safe

KEY FINDINGS SUMMARY
====================

Question: Can HTA files execute silently without user prompts?
Answer: YES, COMPLETELY SILENT ✓

Evidence:
✓ No visible windows (can be hidden)
✓ No UAC prompts (if not elevating)
✓ No security warnings
✓ No confirmation dialogs
✓ Commands execute with hidden windows
✓ Registry modified without notification
✓ Files created silently
✓ Persistence established without user interaction

Question: Which browsers are vulnerable?
Answer: Only mshta.exe is vulnerable
- Chrome: Not vulnerable (no ActiveX)
- Firefox: Not vulnerable (no ActiveX)
- Edge: Not vulnerable (no ActiveX)
- IE11: Limited risk (deprecated, can be disabled)
- mshta.exe: HIGHLY VULNERABLE (full system access)

Question: Can malware persist silently?
Answer: YES, completely silently
- Registry Run key modification
- Scheduled task creation
- Startup folder population
- All without user knowledge or consent

Question: How to prevent?
Answer: Multiple layers required
1. Disable .hta file association
2. Deploy AppLocker or WDAC
3. Monitor registry modifications
4. Deploy EDR/XDR for detection
5. Train users on threats


TECHNICAL SUMMARY
=================

HTA Execution Chain:
User opens file → mshta.exe launches → HTA runs with hidden window →
ActiveX objects accessed → Commands executed (invisible) →
Registry modified (silent) → Persistence established → Malware persists

Capabilities Available:
- WScript.Shell: Command execution, registry access
- FileSystemObject: File creation/modification
- WbemLocator: WMI access, process management
- Network access: Download additional payloads

Silent Execution Methods:
- Window state control (HTA:APPLICATION WINDOWSTATE)
- Shell.Run with window style 0 (hidden)
- Async execution (no wait for completion)
- Error suppression (no error dialogs)

Persistence Methods:
- Registry Run keys (HKCU\...\Run)
- Scheduled tasks (via WMI)
- Startup folder files
- Scheduled events (WMI)
