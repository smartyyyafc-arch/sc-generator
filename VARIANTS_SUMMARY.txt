HEX DECODER VARIANTS - SUMMARY AND COMPARISON

Three optimized hex decoder variants for different payload types, each with
specialized features, optimizations, and execution methods.

================================================================================
VARIANT 1: COMMAND DECODER
================================================================================

Purpose: Shell commands (cmd.exe, powershell.exe)
Optimization: ASCII fast path for 0x20-0x7E range
Execution: Direct WScript.Shell.Run()
Size: ~500-600 bytes

Key Features:
  • Fast path optimization for common ASCII characters
  • Direct command execution without temporary files
  • Minimal code overhead
  • Randomized variable names
  • No file cleanup needed

Use Cases:
  ✓ Single-line commands
  ✓ PowerShell one-liners
  ✓ Cmd.exe commands
  ✓ Fast execution payloads
  ✓ Minimal code size requirements

Example:
  Command: powershell.exe -NoProfile -Command "Write-Host 'Test'"
  Hex: 706f7765727368656c6c2e657865202d4e6f50726f66696c65...
  
  Generated VBS:
  - Function DecCmd_RANDOM(hexStr)
  - Decodes hex to command string
  - Calls CreateObject("WScript.Shell").Run(decoded)
  - Returns immediately

Performance:
  • Encoding: O(n) linear
  • Decoding: O(n) linear with ASCII fast path
  • Execution: Immediate via Shell.Run()

Metadata:
  {
    'type': 'command',
    'payload_type': 'Shell Command',
    'optimization': 'ASCII fast path',
    'command_length': N,
    'hex_length': N*2,
    'execute': True/False
  }

================================================================================
VARIANT 2: SCRIPT DECODER
================================================================================

Purpose: VBScript, batch, PowerShell scripts with multiple lines
Optimization: Full character support including CR/LF/Tab
Execution: Via cscript.exe in temporary file, auto-cleanup
Size: ~800-1200 bytes

Key Features:
  • Full character support (all ASCII values)
  • Special handling for CR (0x0D), LF (0x0A), Tab (0x09)
  • Temporary file creation and cleanup
  • Execution via cscript.exe
  • Preserves script formatting
  • Automatic file deletion after execution

Use Cases:
  ✓ Multi-line VBScript payloads
  ✓ Scripts with control characters
  ✓ Batch scripts (.bat, .cmd)
  ✓ PowerShell scripts with special formatting
  ✓ Complex command sequences
  ✓ Payload requiring cleanup after execution

Example:
  Script:
  ' Test Script
  WScript.Echo "Hello"
  CreateObject("WScript.Shell").Run "notepad.exe"
  
  Generated VBS:
  - Function DecScript_RANDOM(hexStr)
  - Handles vbLf, vbCr, vbTab
  - Creates temporary .vbs file
  - Executes via cscript.exe
  - Deletes temporary file

Performance:
  • Encoding: O(n) linear
  • Decoding: O(n) with Select/Case branching
  • Execution: Via cscript.exe (subprocess)
  • Cleanup: Automatic file deletion

Metadata:
  {
    'type': 'script',
    'payload_type': 'Script File',
    'optimization': 'Full character support with control sequences',
    'script_length': N,
    'hex_length': N*2,
    'execution_method': 'cscript.exe via temporary file',
    'execute': True/False
  }

File Handling:
  Temp File: %TEMP%\tmpRNDNUM.vbs
  Execution: cscript.exe TEMP_FILE
  Cleanup: fso.DeleteFile(TEMP_FILE)

================================================================================
VARIANT 3: BINARY DECODER
================================================================================

Purpose: Binary executables, DLLs, raw binary data
Optimization: Byte array with integrity verification
Execution: Direct execution or via RunDLL32
Size: ~600-900 bytes

Key Features:
  • Byte array storage (no text encoding issues)
  • Full 0x00-0xFF byte value support
  • Integrity verification (size check)
  • ADODB.Stream for binary file writing
  • Direct binary execution
  • Automatic cleanup after execution
  • No encoding loss for binary data

Use Cases:
  ✓ PE executables (.exe)
  ✓ Dynamic Link Libraries (.dll)
  ✓ Raw binary payloads
  ✓ When integrity verification is needed
  ✓ Binary data that can't use text encoding
  ✓ RunDLL32 compatibility required

Example:
  Binary: MZ header + PE payload (4D 5A 90 00...)
  
  Generated VBS:
  - Function DecBin_RANDOM(hexStr)
  - Creates byte array
  - Converts hex pairs to bytes
  - Verifies size: UBound(array) + 1 == expected
  - Uses ADODB.Stream to write binary
  - Executes binary file
  - Deletes temporary file

Performance:
  • Encoding: O(n) linear
  • Decoding: O(n) with array allocation
  • File Write: ADODB.Stream (efficient binary I/O)
  • Execution: Direct via Shell.Run()
  • Integrity Check: O(1) array bounds check

Metadata:
  {
    'type': 'binary',
    'payload_type': 'Binary Executable',
    'optimization': 'Byte array with integrity verification',
    'binary_length': N,  # in bytes
    'hex_length': N*2,   # in characters
    'integrity_check': 'Expected N bytes',
    'execution_method': 'Direct execution via temporary file',
    'execute': True/False
  }

Integrity Verification:
  If UBound(byteArray) + 1 <> EXPECTED_SIZE Then
      WScript.Echo "Binary integrity check failed"
      WScript.Quit 1
  End If

File Handling:
  Temp File: %TEMP%\binRNDNUM.exe
  Write: ADODB.Stream in binary mode (Type = 1)
  Execution: Shell.Run(TEMP_FILE)
  Cleanup: fso.DeleteFile(TEMP_FILE)

================================================================================
SELECTION GUIDE
================================================================================

Choose COMMAND DECODER when:
  • Executing single-line shell commands
  • Need smallest code footprint
  • Fastest execution is critical
  • No file I/O operations needed
  • PowerShell one-liners
  • Cmd.exe commands

Choose SCRIPT DECODER when:
  • Running multi-line scripts
  • Need special character handling (CR/LF/Tab)
  • VBScript or batch script payload
  • Complex command sequences
  • Automatic cleanup is beneficial
  • Execution isolation via subprocess

Choose BINARY DECODER when:
  • Executing PE files (.exe, .dll)
  • Running compiled binaries
  • Payload integrity verification needed
  • Cannot risk encoding/decoding corruption
  • Binary data with null bytes (0x00)
  • Need ADODB.Stream for binary I/O

SECURITY NOTES
================================================================================

Detection Points:
  • Hex-to-text conversion patterns
  • CreateObject("WScript.Shell")
  • ADODB.Stream usage
  • Temporary file creation
  • Process execution patterns

Evasion Techniques:
  • Randomized variable names (built-in)
  • Hex encoding obfuscation (built-in)
  • Temporary files auto-deleted (script, binary only)
  • No clear executable paths visible

Recommendations:
  • Use with additional obfuscation layers
  • Encrypted payload transport
  • Consider code signing for binaries
  • Monitor WScript.Shell usage
  • Track temporary file creation
