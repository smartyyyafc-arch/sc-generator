TROUBLESHOOTING
================================================================================

Q: COM object "X" not available - what does this mean?
A: Object is not registered on this system
   Solution: Check if application is installed (Office, IE, etc.)
             Run: COM_Execution_Examples.ps1::Get-COMObjectsAdvanced()

Q: Access denied when writing registry
A: Insufficient privileges
   Solution: Try HKCU instead of HKLM
             Run as Administrator for HKLM access

Q: Task Scheduler task creation fails
A: Requires administrator privileges
   Solution: Run PowerShell as Administrator
             Some older systems may have restrictions

Q: JavaScript/VBScript in IE doesn't execute
A: Security/sandbox restrictions
   Solution: Use HTMLFile (MSHTML) instead
             May be blocked by policy

Q: Detection/antivirus blocking execution
A: Detected as malicious
   Solution: Use obfuscation techniques from COM_Advanced_Techniques.ps1
             Try different COM objects (ScriptControl, ADODB.Stream)
             Review evasion section in COM_Quick_Reference.txt

================================================================================

- WScript.Shell.Run("cmd.exe") most monitored
- InternetExplorer.Application instantiation obvious
- Office VBA execution highly visible
- Registry persistence keys well-known

STEALTH FACTORS:

- MSHTML less common than IE

- Chained execution confuses static analysis

RECOMMENDATION:
- Layer multiple techniques
