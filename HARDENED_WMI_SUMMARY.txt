================================================================================
HARDENING TECHNIQUES IMPLEMENTED
================================================================================

LAYER 1: COMMAND STRING OBFUSCATION
------------------------------------
Technique 1.1 - Base64 Encoding with Runtime Decoding
  Goal: Hide command in base64, decode at execution time
  Impact: Prevents plaintext string scanning
  Implementation: MSXML2.DOMDocument decoder

Technique 1.2 - Character Array Concatenation (Chr() Arrays)
  Goal: Break strings into Chr() functions
  Impact: Defeats pattern matching, no readable strings
  Implementation: Each character as Chr(ASCII_CODE)

Technique 1.3 - String Concatenation with Spacing
  Goal: Split encoded strings into small chunks
  Impact: Regex patterns can't match whole command
  Implementation: Chunks concatenated with & operators

Technique 1.4 - Hex Encoding with Character Decoding
  Goal: Complete hex encoding of command
  Impact: Maximum obfuscation, loop-based decoding
  Implementation: Hex pairs converted to characters via CLng() + Chr()


LAYER 2: WMI CLASS NAME OBFUSCATION
------------------------------------
Technique 2.1 - Dynamic Class Name Construction
  Goal: Build "Win32_Process" at runtime, not in source
  Impact: Class instantiation strings not visible to detection
  Implementation: Class names as Chr() arrays or concatenation

Technique 2.2 - WMI Query Variable Construction
  Goal: Assemble queries from parts at runtime
  Impact: "Select * from Win32_Process" patterns can't be detected
  Implementation: SELECT, FROM, and class names separately concatenated


LAYER 3: VARIABLE NAME RANDOMIZATION
------------------------------------
Technique 3.1 - High-Entropy Random Names
  Goal: Generate unique names each execution
  Impact: Signature-based detection fails on variable names
  Implementation: 12+ character random alphanumeric suffixes

Technique 3.2 - Cached Variable Reuse
  Goal: Avoid redundant variable declarations
  Impact: Smaller payload footprint, less pattern surface


LAYER 4: WMI EXECUTION METHOD VARIATIONS
-----------------------------------------
Technique 4.1 - ExecMethod() Instead of Create()
  Goal: Use method invocation pattern instead of direct call
  Impact: ExecMethod() is less commonly monitored
  Implementation: Methods_(), InParameters, SpawnInstance_(), ExecMethod()

Technique 4.2 - Asynchronous Event Sink Execution
  Goal: Non-blocking execution via event callbacks
  Impact: Reduces WMI-specific event log entries
  Implementation: Event sink callback model for async execution

Technique 4.3 - WMI Registry Bridge Execution
  Goal: Indirect execution via registry intermediary
  Impact: Splits execution path, confuses correlation
  Implementation: StdRegProv access, registry-based command channel


LAYER 5: EXECUTION TIMING & FLOW CONTROL
-----------------------------------------
Technique 5.1 - Execution Delay Randomization
  Goal: Add random delays between operations
  Impact: Timeline analysis defeated, execution less distinctive
  Implementation: Rnd() based delays, 100-5100ms range

Technique 5.2 - Multi-Stage Execution Chain
  Goal: Spread indicators across multiple stages
  Impact: No single event shows complete picture
  Implementation: Decode stage → Build stage → Execute stage


LAYER 6: DETECTION & EVASION
----------------------------
Technique 6.1 - Sandbox Detection
  Goal: Detect analysis/sandbox environment
  Impact: Avoids execution in detection environment
  Implementation: WMI connectivity check, process count validation

Technique 6.2 - Anti-Analysis Script Re-execution
  Goal: Bypass command-line triggered analysis hooks
  Impact: Hidden execution bypasses initial detection
  Implementation: Argument checking, hidden window execution

1. BASE64 ENCODING
   - Original:  cmd.exe /c whoami
   - Encoded:   Y21kLmV4ZSAvYyB3aG9hbWk=
   - Decoder:   MSXML2.DOMDocument.CreateElement()
   - Runtime cost: Very Low

2. CHARACTER ARRAY (Chr())
   - Original:  Win32_Process
   - Obfuscated: Chr(87) & Chr(105) & Chr(110) & Chr(51) & ... & Chr(115)
   - Length: 16 chars → 249 chars with Chr() encoding
   - Runtime cost: Low

3. STRING CONCATENATION
   - Original:  powershell.exe
   - Split:     "powe" & "rshe" & "ll.e" & "xe"
   - Benefit: Defeats regex "powershell.exe" patterns
   - Runtime cost: Very Low

4. HEX ENCODING
   - Original:  cmd.exe
   - Hex:       636d642e657865
   - Decoder loop: For i=1 to Len(h) Step 2 → Chr(CLng("&H"&Mid(h,i,2)))
   - Runtime cost: Low-Medium
