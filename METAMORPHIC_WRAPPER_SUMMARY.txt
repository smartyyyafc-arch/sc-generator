ENCODING STRATEGIES
================================================================================

Strategy 1: LINEAR (ID=1)
- Classic multi-layer: Base64 → Hex → Array
- Full intermediate exposure
- Use: Compatibility and inspection

Strategy 2: REVERSE_LINEAR (ID=2)
- Minimal structure returning only array
- No intermediate states
- Use: Minimal payload size

Strategy 3: NESTED_HIDDEN (ID=3)
- Deep nesting with hidden intermediate states
- Structure: { data: { nested: { payload: array } } }
- Use: Hide transformation steps

Strategy 4: METADATA_INTERLEAVED (ID=4)
- Metadata scattered throughout payload
- Confuses automated parsers
- Use: Mixed data obfuscation

Strategy 5: FLAT_INDEXED (ID=5)
- Object-based array with numbered indices
- Structure: { __type, __len, _0, _1, ... }
- Use: Serialization format variation

Strategy 6: BASE64_ONLY (ID=6)
- Direct Base64 without intermediate layers
- Minimal transformation overhead
- Use: Performance-sensitive scenarios

Strategy 7: HEX_ONLY (ID=7)
- Hex representation split into random chunks
- Dynamic chunk sizes prevent pattern matching
- Use: Size-based detection evasion

Strategy 8: DEEP_NESTED_DECOYS (ID=8)
- Multiple nesting levels with decoy data
- Maximum obfuscation with false paths
- Use: High-security scenarios

Strategy 9: SPLIT_ARRAY (ID=9)
- Array split across multiple fields
- Prevents incomplete payload detection
- Use: Fragmentation evasion

Strategy 10: OBJECT_ARRAY (ID=10)
- Object with hex-based property names
- Property names encode position
- Use: Property-based detection evasion

METAMORPHIC METADATA
================================================================================

Every encoded payload includes metamorphic metadata:

{
  "__metamorphic": {
    "version": 1,
    "execution": 0,
    "strategy": 1,
    "strategyName": "LINEAR",
    "timestamp": 1782751066627,
    "seed": 0.123456789,
    "nonce": "abc123",        // Optional
    "decoyField": "def456"    // Optional
  },
  "payload": { ... }
}

Fields:
- version: Protocol version for future compatibility
- execution: Execution count (increments per encode)
- strategy: Numeric ID (1-10)
- strategyName: Human-readable name
- timestamp: Unix timestamp
- seed: Original seed value
- nonce: Random value (with randomizeMetadata=true)
- decoyField: Fake field name (with randomizeMetadata=true)

STRATEGY SELECTION ALGORITHM
================================================================================

Selection is deterministic based on:
1. Seed: Initial entropy value
2. Execution Count: How many encode() calls made
3. Input: The data being encoded

Algorithm:
  hash = (seed + executionCount + input) % numberOfStrategies
  selectedStrategy = strategies[hash]

Properties:
- Same seed + execution sequence = same strategy sequence
- Different seeds = different strategy sequences
- Predictable per seed, unpredictable to observers
- No external randomness (unless morphing enabled)

ADVANCED MORPHING FEATURES
================================================================================

1. DECOY ADDITION
   When addDecoys=true, payload wrapped with fake data:

   Before: { array: ["4d", "79", ...] }
   After:  {
     _decoy1: "fake",
     _decoy2: { nested: "fake" },
     _decoy3: [0.123, 0.456, 0.789],
     data: { array: ["4d", "79", ...] }
   }

   Effect: Observers see additional data paths

2. VARIABLE NESTING
   When varyNesting=true, payload wrapped in 1-3 nesting levels:

   Base: { array: [...] }
   Depth 1: { _nest0: { array: [...] } }
   Depth 2: { _nest1: { _nest0: { array: [...] } } }
   Depth 3: { _nest2: { _nest1: { _nest0: { array: [...] } } } }

   Effect: Variable JSON depth prevents depth-based detection

3. METADATA RANDOMIZATION
   When randomizeMetadata=true, metadata includes random values:

   {
     "nonce": "h3k2j",
     "decoyField": "x9q2w"
   }

   Effect: No two payloads have identical metadata

USAGE EXAMPLES
================================================================================

Example 1: Basic Usage
```javascript
const { MetamorphicWrapper } = require('./metamorphic-wrapper');
const wrapper = new MetamorphicWrapper(42);
const encoded = wrapper.encode('Hello World');
const decoded = wrapper.decode(encoded);
```

Example 2: Advanced Morphing
```javascript
const { AdvancedMetamorphicWrapper } = require('./metamorphic-wrapper');
const wrapper = new AdvancedMetamorphicWrapper();
wrapper.configureMorphing({
  randomizeMetadata: true,
  addDecoys: true,
  varyNesting: true
});
const encoded = wrapper.encode('Secret');
const decoded = wrapper.decode(encoded);
```

Example 3: Payload Analysis
```javascript
const { analyzeMetamorphism } = require('./metamorphic-wrapper');
const analysis = analyzeMetamorphism(encoded);
console.log(analysis.strategy);      // Strategy name
console.log(analysis.depth);         // Nesting depth
console.log(analysis.payloadShape);  // Root-level keys
```

SECURITY ANALYSIS
================================================================================

Strengths:
✓ Non-deterministic payloads (same data, different output)
✓ Seed-based reproducibility
✓ Multiple strategies prevent single-strategy analysis
✓ Nested obfuscation with multiple complexity layers
✓ Metamorphic metadata confuses automated parsing
✓ Optional decoy data creates false paths
✓ Variable structure prevents pattern matching

Limitations:
✗ Metadata exposes strategy ID
✗ Deterministic with known seed
✗ Layer analysis still shows Base64→Hex→Array fundamentally
✗ Size increases with morphing
✗ Nesting keys (_nest0, _nest1) are identifiable

Recommendations:
1. Don't reuse payloads - generate fresh each time
2. Randomize seeds per session
3. Enable all morphing for sensitive data
4. Combine with transport security (HTTPS/TLS)
5. Monitor metadata exposure
6. Test compatibility across strategies
7. Use with encryption for critical data
