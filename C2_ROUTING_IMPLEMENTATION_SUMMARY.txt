CORE ROUTING LOGIC
================================================================================

FINGERPRINT STRUCTURE:
  Each beacon has multiple weighted components:
  • BEACON_ID (unique identifier)
  • SYSTEM_CONFIG (OS, hardware, architecture)
  • NETWORK_CONFIG (IP addresses, MAC addresses)
  • PROCESS_INFO (running processes, services)
  • BEHAVIORAL (timing patterns, intervals)
  • CRYPTO (cryptographic material, cert hashes)

ROUTING DECISION FLOW:
  1. Beacon submission with fingerprint
  2. Fingerprint validation and integrity check
  3. Sort applicable routing rules by priority
  4. For each rule:
     a. Match fingerprint components against pattern
     b. Calculate weighted confidence score
     c. If confidence >= threshold: mark as match
  5. Select best-matching rule
  6. Select server from rule targets using strategy
  7. Register beacon with selected server
  8. Return routing decision with alternatives

FINGERPRINT MATCHING:
  • EXACT: Requires exact value match (confidence: 0 or 1)
  • FUZZY: Character overlap based (confidence: 0-1, with tolerance)
  • PROBABILISTIC: Jaccard similarity (confidence: 0-1)
  • HIERARCHICAL: Multi-level with component weights

ROUTING STRATEGIES:
  1. DIRECT - Use first target server
  2. LOAD_BALANCED - Route to least-loaded server
  3. FAILOVER - Primary + automatic fallback
  4. ROUND_ROBIN - Deterministic sequential selection
  5. GEOLOCATION - Based on beacon location
  6. LATENCY_OPTIMIZED - Lowest latency server
  7. RANDOMIZED - Random server selection

================================================================================
USAGE EXAMPLES
================================================================================

PYTHON QUICK START:
  from c2_fingerprint_router import *

  # Initialize router
  router = C2FingerprintRouter()

  # Register servers
  primary = router.register_server('Primary', 'c2.example.com', 443)

  # Create routing rule
  router.create_routing_rule(
      name='Windows Systems',
      fingerprint_pattern={'system_config': 'Windows.*'},
      target_servers=[primary],
      matching_algorithm=MatchingAlgorithm.FUZZY,
      priority=10
  )

  # Register beacon
  components = [
      FingerprintComponent(FingerprintType.SYSTEM_CONFIG, 'Windows-10-x64', 2.0)
  ]
  fingerprint = router.register_beacon_fingerprint('beacon-001', components)

  # Route beacon
  decision = router.route_beacon('beacon-001', fingerprint)
  print(f"Route to: {decision.selected_server.address}:{decision.selected_server.port}")


JAVASCRIPT QUICK START:
  const { C2FingerprintRouter, FingerprintComponent, FingerprintType } = require('./c2-fingerprint-router');

  const router = new C2FingerprintRouter();
  const primary = router.registerServer('Primary', 'c2.example.com', 443);

  const components = [
      new FingerprintComponent(FingerprintType.SYSTEM_CONFIG, 'Windows-10-x64', 2.0)
  ];

  const fingerprint = new (require('./c2-fingerprint-router').BeaconFingerprint)('beacon-001', components);
  router.registerBeaconFingerprint('beacon-001', components, primary);

  const decision = router.routeBeacon('beacon-001', fingerprint);
  console.log(`Route to: ${decision.selectedServer.address}:${decision.selectedServer.port}`);

TROUBLESHOOTING
================================================================================

BEACON NOT ROUTING:
  1. Verify beacon is registered: router.beacon_fingerprints
  2. Check routing rules are enabled: rule.is_enabled
  3. Verify rule has target servers: rule.target_servers
  4. Test fingerprint matching: router.match_fingerprint_to_rule()
  5. Check server is active: server.is_active

SERVER NOT RECEIVING BEACONS:
  1. Verify server is active: server.is_active
  2. Check server capacity: server.getLoadPercent()
  3. Verify server in rules: rule.target_servers
  4. Check rule priorities: sorted by priority descending
  5. Test with forced routing: router.route_beacon(..., force_server_id=...)

POOR MATCHING CONFIDENCE:
  1. Check fingerprint components exist and valid
  2. Verify SYSTEM_CONFIG component present
  3. Check component weights sum reasonably
  4. Try fuzzy matching instead of exact
  5. Lower match_threshold
  6. Review rule patterns
