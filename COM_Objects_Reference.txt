1. PRIMARY COM OBJECTS (Specified in Request)
================================================================================

1.1 Shell.BrowserHelper
    ProgID: Shell.BrowserHelper
    CLSID: {64AB4BB7-111E-11D0-8D34-00A0C90F2719}
    Description: Provides browser helper functionality
    Methods: ExecuteCommand(), Execute()
    Execution Context: User context
    Requirements: Windows, Registry access
    Risks: Can execute arbitrary commands

1.2 InternetExplorer.Application
    ProgID: InternetExplorer.Application
    CLSID: {0002DF01-0000-0000-C000-000000000046}
    Description: Internet Explorer COM automation object
    Methods:
        - Navigate(URL)
        - ExecWB() - Execute Web Browser commands
        - PutProperty() / GetProperty()
        - CreatePrivacyManager()
    Execution Context: User context
    Requirements: IE installed (legacy systems), Registry access
    Capabilities: JavaScript execution, HTML rendering, Script evaluation
    Risks: Can execute JavaScript/VBScript in document context

1.3 MSHTML (Microsoft HTML)
    ProgID: HTMLFile
    CLSID: {25336920-03F9-11CF-8FD0-00AA00686F13}
    Description: HTML document object
    Interfaces: IHTMLDocument2, IHTMLDocument3
    Methods: write(), open(), close()
    Execution Context: User context via script engine
    Requirements: MSHTML.dll available
    Capabilities: Execute embedded scripts, render HTML, access DOM
    Risks: Can execute VBScript/JavaScript via <script> tags

2. ALTERNATIVE COM OBJECTS FOR CODE EXECUTION
================================================================================

2.1 WScript.Shell
    ProgID: WScript.Shell
    CLSID: {72C24DD5-D70A-438B-8A42-98424B88AFB8}
    Description: Windows Script Host Shell object
    Methods:
        - Run(strCommand, intWindowStyle, bWaitOnReturn)
        - Exec(strCommand)
        - CreateShortcut()
        - GetSpecialFolder()
        - RegWrite/RegRead/RegDelete
        - SendKeys()
    Usage: Direct command execution
    Context: User context
    Availability: All Windows systems
    Examples:
        $shell = New-Object -ComObject "WScript.Shell"
        $shell.Run("cmd.exe /c whoami", 1, $false)

3. EXECUTION METHODS SUMMARY
================================================================================

Direct Execution Methods:
├── WScript.Shell.Run()              - Command-line execution
├── WScript.Shell.Exec()             - Command with I/O capture
├── Shell.BrowserHelper.Execute()    - Browser helper execution
├── Excel.Application.Run()          - VBA macro execution
├── Word.Application.Run()           - VBA macro execution
├── ScriptControl.Eval()             - Script evaluation
└── InternetExplorer.ExecWB()        - Web browser commands

Script-Based Methods:
├── MSHTML document script tags      - Embedded HTML/JavaScript
├── InternetExplorer JavaScript      - IE document scripting
├── ScriptControl.AddCode()          - VBScript/JScript
└── Office VBA macros                - Embedded macros

File I/O Methods:
├── ADODB.Stream                     - File operations
├── Scripting.FileSystemObject       - File system access
├── MSXML2.XMLHTTP                   - Network transfers
└── Shell.Application.NameSpace()    - Folder/file navigation

Persistence Methods:
├── ScheduledTasks.TaskScheduler     - Task scheduling
├── WScript.Shell.RegWrite()         - Registry persistence
└── Office autostart macros          - Document execution

4. DETECTION EVASION TECHNIQUES
================================================================================

1. Use less-monitored COM objects (ScriptControl, ADODB.Stream)
2. Execute via Office documents with auto-executing macros
3. Use Task Scheduler for persistence (requires admin)
4. Encode payloads in registry or alternate data streams
5. Chain multiple COM objects to obfuscate execution
6. Use file-based execution with hidden attributes
7. Leverage WMI alongside COM for hybrid execution

5. POWERSHELL COM INSTANTIATION PATTERNS
================================================================================

# Basic instantiation
$obj = New-Object -ComObject "ProgID"

# By CLSID
$obj = New-Object -ComObject "{GUID}"

# With error handling
$obj = New-Object -ComObject "ProgID" -ErrorAction SilentlyContinue

# Type cast
[Type]$type = [System.Type]::GetTypeFromProgID("ProgID")
$obj = [Activator]::CreateInstance($type)

# Direct .NET reflection
$type = [System.Type]::GetTypeFromProgID("WScript.Shell")
$instance = [Activator]::CreateInstance($type)

6. DEFENDER/EDR DETECTION BYPASS
================================================================================

Known Detection Patterns:
- WScript.Shell.Run() with cmd.exe/powershell.exe
- InternetExplorer.Application instantiation
- MSHTML script execution
- Office.Application macros

Bypass Techniques:
- Use less common COM objects
- Execute via scheduled tasks
- Use ADODB.Stream for file operations
- Chain multiple objects
- Delay execution with WMI
- Use legitimate admin tools via COM
